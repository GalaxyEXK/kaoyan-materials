## 进程：

## 1. 进程的概念

在多道程序环境下，允许多个程序并发执行，但并发性破坏了程序原本的封闭性，使其执行过程呈现间断性，并可能导致结果不可再现。为有效描述和控制程序的并发行为，操作系统引入了进程（Process）这一核心概念，以支撑操作系统的两大基本特性：并发性与共享性。

为使每个参与并发执行的程序能独立运行，必须为其配置一个专门的数据结构，称为进程控制块（Process Control Block，PCB）。操作系统通过 PCB 记录进程的基本信息和运行状态，从而实现对其的控制与管理。通常，程序段、相关数据段和 PCB 三者共同构成进程实体（也称进程映像）。因此，创建进程的本质是创建其 PCB；相应地，撤销进程即释放该 PCB 及相关资源。

从不同视角出发，进程可有不同的定义，比较典型的定义如下。

1）进程是正在执行的程序实例。

2）进程是程序及其数据从外存加载到内存后，在 CPU 上运行的过程。

3）进程是具有独立功能的程序在一个特定数据集合上的执行活动。

在传统操作系统中，进程被正式定义为：“进程是进程实体的运行过程，是系统进行资源分配和调度的一个独立单位”。这里所说的“系统资源”不仅包括内存空间、I/O设备等硬件资源，也包括CPU的使用权，而CPU的使用权通常通过时间片的分配来实现。正因进程是资源分配与调度的基本单位，它必然不是静态的程序，而必须是一个动态的、具有生命周期的过程性实体。

## 进程的状态与转换：

## 概念：

## 2.1.4 进程的状态与转换

进程在其生命周期中，由于与其他进程的相互制约以及系统运行环境的变化，其状态会不断发生转换。通常，进程具有以下五种状态，其中前三种为基本状态。

1）运行态。进程正在 CPU 上执行。在单 CPU 中，任一时刻最多只有一个进程处于运行态。

2）就绪态。进程已获得除 CPU 外的所有必要资源，一旦获得 CPU，便可立即投入运行。系统中可能有多个就绪进程，通常将它们组织成一个队列，称为就绪队列。

考点追踪 执行中断处理程序时进程的状态（2023）

3）阻塞态，也称等待态。进程因等待某一事件（如某个资源可用、I/O操作完成等）而暂停运行。此时即使CPU空闲，该进程也无法执行。系统通常将处于阻塞态的进程组织成一个阻塞队列，甚至根据阻塞原因的不同，还可进一步划分为多个子队列。

4）创建态。进程正处于创建过程中，尚未进入就绪态。创建进程包括多个步骤：首先申请一个空白的 PCB，并向其中填写用于控制和管理进程的信息；然后为该进程分配运行时所需的资源（如内存空间）；最后，当所有必要资源都已到位，系统将该进程转入就绪态，并插入就绪队列。创建态是一个短暂的中间状态，正常情况下不会长期停留。

5）终止态。进程已完成执行（无论是正常结束还是被强制终止），正在等待系统回收其资源。此时，进程不再参与调度，但其PCB等信息可能暂时保留，直至完成最终清理。

区分就绪态与阻塞态：就绪态是指进程仅缺少 CPU，只要获得 CPU 就可立即运行；而阻塞态是指进程需要其他资源（除 CPU 外）或等待某一事件。之所以将 CPU 与其他资源分开，是因为在分时系统的时间片轮转机制中，每个进程分得的时间片很短（通常为几毫秒），因此进程在运行过程中会频繁地在运行态与就绪态之间切换；而其他资源（如外设）的分配或事件（如 I/O 完成）的发生往往需要较长时间，导致进程进入阻塞态的频率远低于就绪态。由此可见，就绪态和阻塞态在进程生命周期中代表了两种性质完全不同的等待情形。

图 2.2 说明了五种进程状态之间的转换关系。其中，三种基本状态之间的转换如下。

\- 就绪态 $\rightarrow$ 运行态：处于就绪态的进程被调度程序选中，获得 CPU 的使用权（例如分配到一个时间片），随即由就绪态转换为运行态。

\- 运行态 $\rightarrow$ 就绪态：处于运行态的进程在时间片用完后，必须主动让出CPU，从而转回就绪态；此外，在可剥夺式调度系统中，若有更高优先级的进程变为就绪，则当前运行的进程也会被强制切换回就绪态，以便让更高优先级的进程执行。

\- 运行态 $\rightarrow$ 阻塞态：当运行中的进程通过系统调用请求某项服务（如发起I/O操作），而该请求无法立即满足（需等待I/O完成），进程便会主动进入阻塞态。需注意，并非所有系统调用都会导致阻塞，只有那些需要等待外部事件的操作才会引发状态转换。

\- 阻塞态 $\rightarrow$ 就绪态：当进程所等待的事件发生时（如I/O操作完成），相应的中断处理程序会将其状态由阻塞态修改为就绪态，并重新插入就绪队列，等待下一次调度。

值得注意的是，进程从运行态变为阻塞态是一种主动行为（由自身发起的系统调用触发），而从阻塞态变为就绪态则是一种被动行为，依赖于外部事件的发生或其他进程的协助。

## 五、哪些事件属于“唤醒事件”？

严格来说，某事件必须满足两个条件，才算对某进程的唤醒事件：

1. 该进程原来处于阻塞态

2. 该事件正是它所等待的事件

核心形式是:

```txt
等待事件未发生
阻塞态
|
| 等待事件发生
↓
就绪态
```

## 并发进程：

只有等待队列中确实有进程，才会唤醒。

## 五、并发进程的重要特征

## 1. 动态性

进程是程序的一次执行过程。

程序本身是静态的，例如磁盘上的可执行文件；进程是动态的，包括：

\- 创建；

\- 执行；

\- 状态转换；

\- 资源申请与释放；

\- 最终终止。

## 2. 间断性

进程不会始终连续执行，而是：

<div class="mineru-algorithm" style="white-space: pre-wrap; font-family:monospace;">
执行一段 $\rightarrow$ 暂停 $\rightarrow$ 等待 $\rightarrow$ 再执行
</div>

形成间断推进。

## 3. 异步性

各进程按照各自独立、不可预知的速度向前推进。

这里的“异步”不是说完全混乱，而是说：

进程推进的相对速度和先后顺序无法事先精确确定。

例如：

P1先执行还是P2先执行？

P1运行多久后被切换？

P2等待的I/O什么时候完成？

这些通常都不能由应用程序直接决定。

## 4. 相互制约性

并发进程之间可能产生两种制约关系。

## 间接制约：互斥

多个进程争用同一个资源。

例如：

```txt
P1、P2都要使用打印机
```

打印机同一时刻只能供一个进程使用，因此需要互斥。

## 直接制约：同步

一个进程必须等待另一个进程完成某项工作。

例如生产者—消费者问题：

生产者产生数据消费者使用数据

如果缓冲区为空，消费者必须等待生产者产生数据。

## 5. 不可再现性

如果没有同步控制，进程的不同交错顺序可能导致不同结果。

它与以下概念紧密联系：

```txt
异步性
↓
执行顺序不确定
↓
共享变量访问发生交错
↓
产生竞态条件
↓
结果可能不可再现
```

## D. 并发进程的运行结果具有不可再现性

正确。

并发进程的推进速度具有异步性：

\- 哪个进程先执行，不确定；

\- 一个进程执行多少条指令后被切换，不确定；

\- I/O什么时候完成，不确定；

\- 中断什么时候到达，不确定；

\- 哪个进程先获得共享资源，不确定。

因此，在没有同步约束的情况下，同一程序再次执行时，执行顺序可能改变，运行结果也可能改变，这就是不可再现性。

不过要注意一个更严谨的表述：

不可再现性主要针对“并发执行次序”和“未经同步保护的共享数据结果”。

如果程序正确使用了锁、信号量等同步机制，那么虽然底层调度顺序仍可能不同，但最终逻辑结果可以保持正确、可再现。

## 异步性:

异步性是指：

在多道程序环境中，多个进程并发执行时，每个进程会以不可预知的速度断断续续地向前推进。

也就是说，我们通常不能事先准确判断：

\- 某个进程什么时候获得CPU；

\- 它能运行多长时间；

\- 它什么时候被暂停、什么时候恢复；

\- 两个进程谁先执行到某一步、谁先结束。

## 互斥和同步：

## 四、同步：解决“必须按顺序进行”的问题

## 1. 什么是同步

同步是指多个进程在执行过程中，为了完成某个共同任务，需要按照规定的先后顺序推进。

即：

一个进程必须等待另一个进程完成某项操作后，才能继续执行。

例如：

P1：读取数据  
P2：处理数据

显然必须：

P1 读取完成 $\rightarrow$ P2 才能处理

如果 P2 先执行，就没有数据可以处理。

## 三、互斥：解决“不能同时进入”的问题

## 1. 什么是互斥

当多个进程需要使用同一个不可同时共享的资源时，规定：

同一时刻只允许一个进程访问该资源。

这种关系叫作互斥。

例如：

\- 两个进程不能同时使用一台打印机；

\- 多个进程不能同时修改同一个共享变量；

\- 多个进程不能同时修改同一个文件的关键位置；

\- 多个线程不能同时修改同一个链表。

## 十六、“并非所有内容都在物理内存”是什么意思

这是书中第一段的重要内容。

\- 暂时没有对应物理页框。

```txt
↓

↓

↓

```

## 二、地址映射到底是什么意思

地址映射，就是建立程序使用的逻辑地址（虚拟地址）与内存中实际物理地址之间的对应关系。

可以先记成：

```txt
程序给出的地址
逻辑地址/虚拟地址
↓ 地址映射
内存条上的实际位置
物理地址
```

![](第二章 进程与线程(2.1).docx.assets/88b2bf02901fd408efd651db131868588d3c78a066770c7cabd701883347712a.jpg)

例如，程序执行一条指令：

```txt
<//> C
x = 10;
```

CPU需要找到变量 $\times$ 存放在哪里。

但程序通常只知道：

```txt
x 在本进程地址空间中的 1000 号位置
```

它并不知道自己实际被操作系统放到了物理内存的哪个地方。因此，CPU访问内存前，要把逻辑地址1000转换成某个物理地址，例如：

```txt
逻辑地址 1000 → 物理地址 51000
```

这个对应关系就是地址映射。

实际完成转换的过程一般称为：

\- 地址映射

\- 地址变换

\- 地址转换

\- 地址翻译

在很多教材和题目中，这几个词经常近似使用。

## 更严格地区分:

地址映射：建立“逻辑地址对应哪个物理地址”的关系

地址变换：根据这种关系，把某次逻辑地址转换成物理地址

```txt
高地址
```

## 消息传递机制：

操作系统中，微内核与服务器之间通过操作系统的消息传递机制传递信息，这里的服务器是指的CPU吗

不是。这里的服务器不是 CPU，而是指运行在用户态、专门提供某种操作系统服务的服务器进程（server process）。

## 1. “服务器”到底是什么

微内核只把最基础、最关键的功能保留在内核中，例如：

\- 进程/线程的基本调度机制

\- 进程间通信机制

\- 中断和异常的基本处理

\- 少量底层内存管理机制

原来操作系统中的大量功能，则从内核中移出去，做成一个个独立的用户态服务器进程，例如：

<table><tr><td>服务器进程</td><td>提供的服务</td></tr><tr><td>文件服务器</td><td>文件的打开、读写、目录管理等</td></tr><tr><td>设备服务器</td><td>管理设备和设备驱动</td></tr><tr><td>进程服务器</td><td>提供部分进程管理服务</td></tr><tr><td>虚拟存储器服务器</td><td>负责部分虚拟内存管理策略</td></tr><tr><td>网络服务器</td><td>提供网络协议和通信服务</td></tr></table>

王道资料中明确指出，微内核之外的操作系统功能由“一组服务器进程”实现，这些服务器通常以用户态进程的形式运行，例如进程/线程服务器、虚拟存储器服务器等。王道2027操作系统\_OCR

所以：

服务器 = 提供某种系统服务的软件进程，而不是硬件 CPU。

## 信号：

## 六、PCB中为什么要有两个信号位向量

截图中最重要、也最容易看不懂的是这两个位向量。

## 1. 待处理信号向量

它表示：

哪些信号已经发生，但还没有处理。

假设有 8 类信号，用 8 位表示:

```txt
信号编号： 87654321待处理位：00001000
```

第 4 位为 1，表示:

```txt
4号信号已经产生，等待处理
```

假设4号信号是SIGILL，就表示该进程目前有一个非法指令信号等待处理。

信号处理完成后：

```csv
00001000
↓
00000000
```

对应位被清零。

## 2. 信号屏蔽向量

它表示:

当前暂时不允许处理哪些信号。

例如：

```txt
信号编号： 87654321  
屏蔽位： 00001000
```

表示4号信号现在被屏蔽。

这时，即使4号信号已经产生：

```txt
待处理向量：00001000屏蔽向量： 00001000
```

操作系统也不会立刻处理它。

而是把它保留为待处理状态。

等进程解除屏蔽：

```txt
屏蔽向量：00000000
```

此时再处理 4 号信号。

所以：

屏蔽不是删除信号，而是暂缓处理。

可以用下面三个词区分：

<table><tr><td>概念</td><td>含义</td></tr><tr><td>信号产生</td><td>某个事件发生了</td></tr><tr><td>信号待处理</td><td>事件已经记录,但尚未完成处理</td></tr><tr><td>信号屏蔽</td><td>这个信号暂时不允许递送</td></tr></table>

## 七、信号从哪里产生

截图中分成两种来源。

## 1. 内核产生信号

操作系统检测到某些事件后，直接给有关进程产生信号。

例如进程执行非法指令：

```txt
进程执行非法指令
↓
CPU产生异常
↓
进入操作系统内核
↓
内核判断是非法指令
↓
向当前进程产生 SIGILL
```

## 注意这里有一个重要关系：

```txt
硬件异常
↓
操作系统处理异常
↓
操作系统转换为信号通知进程
```

所以：

异常和信号有联系，但不是同一个东西。

非法指令首先是CPU检测出的异常；内核处理异常后，再使用SIGILL告诉进程发生了什么。

## 2. 进程请求发送信号

一个进程可以调用 kill()，请求内核向另一个进程发送信号。

```txt
<» C kill(pid, SIGTERM);
```

过程是：

```txt
发送进程执行 kill()
↓
发生系统调用，进入内核态
↓
内核检查目标PID和权限
↓
修改目标进程PCB中的信号信息
↓
目标进程以后处理该信号
```

为什么进程A不能直接修改进程B的PCB?

因为PCB是操作系统内核的数据结构，普通用户进程不能直接访问。

## 进程的通信：

## 2.1.6 进程的通信

进程通信（IPC）是指进程之间的信息交换。根据通信效率和数据量的不同，可分为低级通信和高级通信两类：低级通信主要用于传递控制信息（如同步、互斥），典型代表是 PV 操作（见 2.3 节）；高级通信用于高效传输大量数据，主要包括共享存储、消息传递和管道通信、信号等方式。

## 1. 共享存储

进程的地址空间通常是相互隔离的，一个进程不能直接访问另一个进程的内存。因此，若要实现高效的数据交换，操作系统提供了共享存储机制：通过特殊的系统调用，创建一段独立的内存区域，并将其映射到多个进程的虚拟地址空间中，使这些进程都能直接读/写该区域。在共享存储方式中，参与通信的进程通过对这一共享区域进行读/写来交换信息，如图2.3所示。由于多个进程可能并发访问同一块内存，必须由用户程序引入同步互斥机制（如信号量的P、V操作），以避免数据竞争或不一致。需要注意的是，操作系统仅负责分配共享内存区并完成地址映射，并不会自动提供同步保护；具体的读/写逻辑与同步控制，均需由用户程序自行设计和实现。

通俗地理解，可以想象甲和乙之间放着一个公共的大布袋：甲把要传递的物品放进布袋，乙再从里面取出。但乙不能直接伸手去拿甲手里的东西，甲也不能直接取走乙的东西，所有交换都必须通过这个公共区域完成。

## 2. 消息传递

当进程之间没有共享内存，或出于安全等考虑不便使用共享存储时，可采用操作系统提供的消息传递机制进行通信。在消息传递系统中，进程间的数据交换以格式化的消息（Message）为单位，通过操作系统提供的发送原语和接收原语进行。这种方式将通信的底层细节封装在内核中，对用户透明，从而简化了应用程序的设计。消息传递是目前应用最广泛的进程间通信机制，在微内核操作系统中，微内核与服务器之间的交互正是基于消息传递。此外，该机制很好地支持多处理器系统、分布式系统和计算机网络，因此也成为这些环境中的主流通信方式。

从管道中读取数据是一次性操作，数据一旦被读出，其占用的缓冲区空间即被释放，供后续写入使用；普通管道仅支持单向通信，若需双向通信，则必须创建两个管道，分别用于两个方向的数据传输。

## 4. 信号

信号（Signal）是一种用于通知进程某个事件已发生的机制。不同的系统事件对应不同的信号类型，每类信号对应一个序号。例如，Linux 内核实现了约 30 种信号，编号通常为 1～30。

在进程的PCB中，用一个 $n$ 位向量（如Linux使用一个32位整型变量）记录该进程当前待处理的信号。当向某进程发送一个信号时，内核会将该信号对应的位置为1；一旦该信号被成功处理，对应位即被清零。此外，PCB中还维护另一个 $n$ 位向量，用于记录被阻塞（屏蔽）的信号。当某一位为1时，表示对应的信号不会被立即处理，而是暂存起来，直到解除阻塞。

信号的发送主要有以下两种方式：

1）内核发送信号。当内核检测到特定的系统事件时，会向相关进程发送相应的信号。例如，若进程执行了非法指令，则内核将向其发送 SIGILL 信号（序号为 4）。

2）由进程发送信号。一个进程可以通过调用 kill() 函数，请求内核向指定进程（需提供目标进程的 PID 和信号序号）发送信号。当然，进程也可以向自身发送信号。

当操作系统从内核态返回用户态时（如系统调用结束），会检查当前进程是否存在未被阻塞的待处理信号。若存在，则立即处理其中一个信号（通常优先处理序号较小的信号）。

信号的处理方式有两种：

1）执行默认的信号处理程序。操作系统为每类信号预设了默认操作。例如，收到 SIGILL 信号的默认操作是终止进程。

2）执行进程自定义的信号处理程序。进程可以为某类信号定义自己的处理函数。例如，可定义收到 SIGILL 时输出 “hello world”，而不是终止进程。

信号处理程序执行结束后，通常会返回到原程序被中断的位置，继续执行后续指令。

## 线程：

基本概念：

## 1. 线程的基本概念

引入进程的目的是使多道程序能够并发执行，从而提高资源利用率和系统吞吐量；而引入线程（Thread）则是为了进一步降低程序并发执行时的时空开销，提升操作系统的并发性能。

线程可被通俗地理解为“轻量级进程”，它是程序执行流的最小单元，也是处理器调度的基本单位。在多线程操作系统中，进程不再作为基本的执行实体，但仍保留与执行相关的状态。所谓进程处于“执行”状态，实际上是指该进程中的某个线程正在运行。线程的主要属性如下。

## (1) 轻量级执行实体

线程本身不拥有独立的系统资源（如地址空间、打开的文件等），但拥有运行所必需的私有数据结构，包括线程 ID、程序计数器、寄存器集合和栈。每个线程都具有唯一的标识符和一个线程控制块（TCB），用于记录其执行上下文（如寄存器状态、栈指针等）。

## (2) 共享代码段

同一进程中的多个线程可并发执行相同的程序代码。例如，当多个用户同时访问一个 Web 服务器时，服务器进程可创建多个线程，各自服务不同的用户请求，显著提升并发能力。

## (3) 资源共享

同一进程内的所有线程共享该进程的代码段、数据段、堆、文件描述符等系统资源。这种机制使得线程间的通信和数据共享非常高效，无须复杂的进程间通信（IPC）机制。

## (4) 独立调度单位

线程是 CPU 调度和执行的基本单位。在单 CPU 系统中，多个线程通过时间片轮转等方式轮流使用 CPU；在多 CPU 系统中，不同线程可并行运行于多个 CPU 核心上。若多个核心同时执行同一进程的不同线程，则能显著缩短该进程的整体处理时间。

## (5) 生命周期

线程从创建开始，经历就绪、运行、阻塞等状态变化，直至最终终止。

引入线程后，进程的内涵发生了重要变化：进程成为除 CPU 外的系统资源分配单位，而线程则成为 CPU 调度和执行的基本单位。当线程切换发生在同一进程内部时，由于地址空间等资源无须切换，其开销远小于进程切换。接下来，将从多个维度对线程与进程进行比较。

“内核级线程”里的“内核级”，指的是由内核管理和调度，不是指线程一直运行在内核态。

## 1. 内核级线程为什么可以在用户态运行？

一个普通程序中的线程，大部分时间执行的都是应用程序代码，例如：

```txt
<» C
int main() {
    int a = 1;
    a = a + 1;
}
```

这些代码不需要操作硬件，也不需要访问内核空间，因此CPU在执行它们时处于用户态。

即使这个线程是一个内核级线程，它执行普通用户程序代码时，仍然处于用户态。

只有当线程需要内核提供服务时，例如：

\- 读写文件

\- 创建线程

\- 申请某些系统资源

\- 进行网络通信

\- 等待I/O

\- 发生缺页异常

它才会通过系统调用、中断或异常进入内核态。

## 所以一个内核级线程的运行过程可能是：

```txt
用户态执行程序代码
↓
调用 read()
↓
进入内核态，执行操作系统代码
↓
读取操作完成
↓
返回用户态，继续执行程序代码
```

因此：

内核级线程不是“运行在内核态的线程”，而是“内核能够直接识别、管理和调度的线程”。

## 线程与进程的比较：

## 2. 线程与进程的比较

## 考点追踪 进程和线程的比较（2012）

1）调度。在传统的操作系统中，进程既是资源拥有者，也是独立调度的基本单位，每次调度都需要进行完整的上下文切换，开销较大。引入线程后，线程成为独立调度的基本单位。在同一进程中，线程切换不会引起进程切换；但若从一个进程的线程切换到另一个进程的线程，则仍会触发进程切换。

2）并发性。在支持线程的操作系统中，并发性得到显著增强：不仅进程之间可以并发执行，同一进程内的多个线程也可以并发执行，甚至不同进程中的线程也能并发执行。这种多层次的并发机制有效提升了系统资源利用率和吞吐量。

3）拥有资源。进程是系统资源分配的基本单位；而线程不拥有独立的系统资源，但拥有运行所必需的私有数据结构。同一进程的所有线程共享该进程的地址空间及资源。

4）独立性。每个进程拥有完全独立的地址空间，默认情况下，其他进程无法直接访问其任何内存区域。相应的，一个进程中的线程对其他进程完全不可见。同一进程内的线程则因共享地址空间而紧密协作，旨在提升并发性能。

5）系统开销。创建或撤销进程时，系统需分配或回收PCB、地址空间、I/O资源等，开销显著；而创建或撤销线程仅需分配栈和少量内核对象，开销很小。类似地，进程切换涉及整个地址空间和资源上下文的切换，而线程切换只需保存和恢复寄存器状态。此外，由于同一进程内的线程共享地址空间，它们之间的同步与通信非常容易实现。

6）支持多处理器系统。对于单线程进程，尽管可以在不同时间被调度到任意 CPU 上运行，但在任一时刻只能在一个 CPU 上执行。而对于多线程进程，系统可将其中的多个线程同时调度到多个 CPU 上并行执行，从而真正发挥多核处理器的性能优势。

这里的私有数据结构，是指：

每个线程为了能独立执行，必须单独保存的一套运行现场。

它不是指线程拥有独立的内存空间，也不是泛指程序中的“私有变量”。王道后文具体列出了：线程 ID、程序计数器、寄存器集合和栈。 王道2027操作系统\_OCR

## 高级调度：

## 二、高级调度是什么

## 1. 定义

高级调度，也叫作业调度。

它从外存的后备队列中挑选若干作业，将其调入内存，并为这些作业建立相应的进程，使其获得参与运行的资格。

简单来说，它解决的是：

哪些作业可以进入内存？

## 2. 状态变化

通常可理解为：

```txt
作业位于外存后备队列
↓ 高级调度
为作业创建进程并调入内存
↓
进程进入就绪态
```

因此，在408题目中常见的说法是：

进程从创建态进入就绪态，与高级调度有关。

## 3. 生活类比

把计算机比作一家餐厅：

\- 餐厅外面排队的人：外存后备队列中的作业

\- 允许某些人进入餐厅：高级调度

\- 进入后坐在等候区：进入内存、处于就绪态

高级调度决定的是：

谁能进入餐厅，而不是谁马上接受服务。

## 4. 调度频率

高级调度的频率一般比较低。

因为一个作业进入内存后，通常会运行较长时间，不会每隔几毫秒就重新进行作业调度。

高级调度还需要控制内存中作业的数量，即控制系统的多道程序度。

## 低级调度:

## 三、低级调度是什么

## 1. 定义

低级调度，也叫进程调度或CPU调度。

它从内存中的就绪队列里选择一个进程，把CPU分配给它。

它解决的是：

已经进入内存的多个就绪进程中，谁现在使用CPU？

```txt
就绪态↓低级调度运行态
```

```txt
P1、P2、P3、P4
```

\- 当前进程时间片用完

\- 当前进程结束

## 中级调度:

## 四、中级调度是什么

中级调度也叫内存调度。

它主要负责把暂时不能运行的进程从内存换出到外存，或者以后再将它换回内存。

它解决的是：

哪些进程暂时离开内存，哪些挂起进程重新回到内存？

例如，某个进程正在等待很慢的I/O事件，而且内存又很紧张：

```txt
内存中的阻塞进程
↓ 换出
外存中的阻塞挂起进程
```

以后事件完成且内存有空间：

```txt
外存中的就绪挂起进程
↓ 换入
内存中的就绪进程
```

中级调度的主要目的通常是：

\- 提高内存利用率

\- 调节多道程序度

\- 改善系统吞吐量

## 临界资源和临界区：

## 一、临界资源是什么

\*\*临界资源（critical resource）\*\*是指：

在一段时间内，只允许一个进程或线程访问的共享资源。

它首先是一个共享资源，但多个进程不能同时使用它，否则可能导致结果混乱或数据错误。

典型临界资源包括：

\- 打印机等独占型设备

\- 可被多个进程修改的共享变量

\- 共享表格、共享队列

\- 某些共享文件

\- 共享内存中的数据结构

王道教材将打印机、变量、表格等列为需要互斥访问的临界资源。 王道2027操作系统\_OCR

## 打印机例子

进程 A 要打印:

AAAAAA

进程 B 要打印:

BBBBBB

如果两个进程同时控制打印机，可能打印成：

AABBAABBABAB

所以打印机在A使用期间，B必须等待。A用完并释放后，B才能使用。

## 因此：

打印机 = 临界资源

## 二、临界区（临界区域）是什么

临界区（critical section）也常被称为临界区域，它是指：

进程中访问临界资源的那一段代码。

也就是说：

\- 临界资源是“被访问的东西”

\- 临界区是“访问这个东西的代码”

这是两者最核心的区别。

## 一、最根本的原因：自定义信号处理函数是用户程序

假设进程为 SIGUSR1 注册了处理函数：

```txt
< C
void handler(int sig) {
    printf("收到信号");
}
```

```txt
这个 handler():
```

\- 属于进程的用户代码；

\- 位于用户地址空间；

\- 应当在用户态执行。

因此，当CPU正在内核态执行系统调用、中断处理程序时，不能突然跳进这个用户态函数。

必须等到内核准备退出，才可以：

1. 检查是否有待处理信号；

2. 修改即将恢复的用户态现场；

3. 把返回地址临时改成信号处理函数入口；

4. 返回用户态;

5. 在用户态执行信号处理函数。

所以所谓“内核处理信号”，并不一定是内核直接运行用户定义的处理函数，而是：

内核安排进程返回用户态后，先执行信号处理函数。

## 二、为什么不能在“用户态→内核态”时处理

用户态进入内核态，通常是因为：

\- 发起系统调用；

\- 发生异常；

\- 发生中断。

这时CPU刚刚进入内核，接下来要处理一项内核任务。例如：

```txt
用户程序执行 read()
↓
陷入内核态
↓
内核处理 read 系统调用
```

假设刚进入内核就发现有信号，然后立刻去执行用户态处理函数，就会出现矛盾：

```txt
刚进入内核处理 read()
↓
还没开始或只处理了一半
↓
又返回用户态执行 handler()
```

这样会使系统调用、中断处理等内核工作被打断，增加以下问题：

\- 内核数据结构可能正处于中间状态；

\- 锁可能还没有释放；

\- 系统调用可能只完成了一半；

\- 内核代码需要考虑被用户处理函数任意打断，设计会非常复杂。

因此，更安全的做法是：

先完成或安全地结束当前内核处理，再在返回用户态的出口统一检查信号。

## 三、“返回用户态”是天然的安全检查点

从内核态返回用户态时，内核本来就要恢复用户进程的现场，例如：

\- 程序计数器 PC;

\- 栈指针 SP;

\- 通用寄存器；

\- 程序状态字。

因此，内核可以很方便地把现场稍作修改：

```txt
原本准备返回的位置：用户程序下一条指令修改后返回的位置：信号处理函数handler
```

信号处理函数执行完后，再通过类似 sigreturn 的机制恢复原来的现场，继续执行原程序。

完整过程可以理解为：

```txt
原用户程序
↓
系统调用/中断
↓
进入内核态
↓
内核完成相关处理
↓
准备返回用户态
↓
检查待处理信号
↓ 有信号
设置返回现场，使其先执行 handler
↓
返回用户态，执行 handler
↓
恢复原现场
↓
继续原用户程序
```

## 一、线程的“速度快”，准确说是管理和切换开销小

选项 B 中的“速度快”是一种简略说法，完整表达应该是：

与进程相比，线程的创建、撤销、切换以及相互通信通常更快。

原因是同一进程中的线程共享：

\- 地址空间

\- 代码段、数据段和堆

\- 打开的文件等系统资源

线程切换时，通常只需切换线程私有的运行现场，如程序计数器、寄存器和栈，而不必更换整个地址空间。因此，同一进程内线程切换的开销远小于进程切换。王道2027操作系统\_OCR

所以这里的“快”实际是：

线程操作开销小，切换和通信更快

并不是说：

同一段代码在线程中执行，CPU计算速度就会更快

例如，一亿次加法：

\- 放在一个进程中执行；

\- 放在该进程的一个线程中执行；

如果都由同一个CPU核心执行，单条加法指令的速度没有区别。

多线程可能缩短整个任务的完成时间，是因为：

1. 多核 CPU 上，多个线程可以真正并行；

2. 某线程等待 I/O 时，其他线程可以继续运行；

3. 线程切换和通信开销较小。

## 二、原子性说的是“不可分割”，不是“速度快”

原子操作的定义是：

一个操作要么全部完成，要么完全不做，执行过程中不会被其他并发执行流观察到中间状态。

例如：

加锁  
读取 $\times$ 修改 $\times$ 写回 $\times$ 解锁

如果把整个过程保护起来，它可以作为一个具有原子效果的操作。

但是，这个操作可能只需要1纳秒，也可能需要1秒。因此：

原子性与执行时间长短没有必然关系

## 三、为什么教材常说“原语执行时间短”？

这里要区分：

\- 原子性：定义性质；

\- 执行时间短：设计要求或常见特点。

原语通常运行在内核态，并且执行期间不允许被打断，或者通过特殊机制保证其不可分割。为了避免长时间占用CPU、关闭中断或阻塞其他任务，原语一般被设计得尽量短。

但是逻辑关系是：

为了减少影响，所以原语应尽量短

而不是：

因为具有原子性，所以它必然执行得快

因此，考试中应记住：

原子性强调“不能被分割和干扰”；速度快强调“完成所需时间少”。两者不是同一概念。

## 一、你最不懂的：什么是高级调度

高级调度又称：

\- 作业调度

\- 长程调度

• High-level Scheduling / Long-term Scheduling

它主要出现在批处理系统中。

1. 先区分“作业”和“进程”

用户把一个任务提交给计算机后，这个任务一开始通常存放在外存的后备队列中。

此时它只是一个等待处理的“作业”，还没有被操作系统正式建立为进程，因此通常：

\- 还没有分配内存；

\- 还没有建立完整的PCB;

\- 还不能进入就绪队列；

\- 更不能占用 CPU 运行。

高级调度的任务就是：

从外存的后备队列中挑选一个或若干作业，将其调入内存，为它分配资源、建立 PCB，从而创建相应的进程，并把进程放入就绪队列。

## 流程可以记成：

```txt
外存中的后备作业
|
| 高级调度（作业调度）
↓
分配内存、建立PCB、创建进程
|
↓
内存中的就绪队列
|
| 低级调度（进程调度）
↓
获得CPU，进入运行态
```

王道教材对三级调度的图示也是：后备队列经过作业调度进入就绪队列，再由进程调度选择进程运行。同时，交互式系统通常直接根据命令创建进程，不一定单独设置作业调度模块。王道2027操作系统\_OCR

## 二、为什么高级调度会“创建新进程”

高级调度前，系统中只有一个等待处理的作业。

高级调度发生后，操作系统会：

1. 从后备队列选择作业；

2. 为作业分配内存等资源；

3. 建立进程控制块 PCB;

4. 建立进程的程序段、数据段等；

5. 将新进程放入就绪队列。

所以：

高级调度不仅是把已有进程调入内存，而是把一个作业转化为进程。

这与中级调度不同。中级调度处理的是已经存在的进程，只是把它换出或换入内存，不会重新创建进程。https://chatgpt.com/g/g-p-6a4147b6a8088191bef869eb87bbe5c0-cao-zuo-xi-tong/c/6a51f92a-76a4-83e8-9826-b68dad2fd290

## 与用户级线程切换相比

内核级线程切换需要：

1. 从用户态进入内核态；

2. 由内核调度器进行调度；

3. 保存、恢复线程上下文；

4. 更新内核中的线程控制信息；

5. 再返回用户态。

而用户级线程切换可以完全在用户空间中完成，只相当于调用线程库中的一段代码。

所以比较关系是：

```txt
用户级线程切换开销
<
同进程内核级线程切换开销
<
进程切换开销（一般情况下）
```

题目问的是“内核级线程相对于用户级线程的优点”，因此不能说内核级线程切换开销更小。
