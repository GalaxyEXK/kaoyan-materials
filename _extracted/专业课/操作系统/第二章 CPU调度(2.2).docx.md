## CPU 调度衡量指标:

## 三、响应时间

## 1. 定义

响应时间是：

$$
\text {响应时间} = \text {第一次获得响应的时刻} - \text {到达时刻}
$$

在CPU调度题中，通常理解为：

$$
\text {响应时间} = \text {第一次开始运行时刻} - \text {到达时刻}
$$

上例中:

$$
T _ {\text {响应}} = 5 - 2 = 3
$$

## 2. 它关注什么

响应时间只关心：

进程提交之后，系统过了多久才第一次理它。

它不关心进程什么时候最终完成。

例如一个进程：

\- 到达后1秒就获得了一次CPU;

\- 但经过很多次抢占，100秒后才完成。

那么：

\- 响应时间可能只有1秒；

\- 周转时间却可能有100秒。

## 四、周转时间

## 1. 定义

周转时间是作业或进程从提交到全部完成所经历的总时间：

$$
\text {周转时间} = \text {完成时刻} - \text {到达时刻}
$$

上例中：

$$
T _ {\mathrm{周转}} = 1 3 - 2 = 1 1
$$

它包含进程从到达到结束之间经历的所有时间。

如果题目中不考虑I/O阻塞，那么：

$$
\text {周转时间} = \text {等待时间} + \text {运行时间}
$$

上例：

$$
1 1 = 6 + 5
$$

## 五、等待时间

## 1. 定义

等待时间是进程在就绪队列中等待CPU的总时间：

$$
\text {等待时间} = \text {进程处于就绪态但没有运行的总时间}
$$

注意是“总时间”，进程可能等待很多次。

上例中：

\- 第一次等待: $5 - 2 = 3$

\- 被抢占后的第二次等待： $10 - 7 = 3$

所以：

$$
T _ {\mathrm{等待}} = 3 + 3 = 6
$$

## 带权周转时间

带权周转时间是在周转时间的基础上，除以进程本身所需的服务时间：

$$
\text {带权周转时间} = \frac {\text {周转时间}}{\text {服务时间}}
$$

其中：

$$
\text { 周转时间 } = \text { 完成时刻 } - \text { 到达时刻 }
$$

“服务时间”就是进程真正占用 CPU 运行所需要的时间，题目中也常写成：

\- 运行时间

\- 执行时间

\- CPU 服务时间

## 3. 高响应比优先 HRRN

全称：

Highest Response Ratio Next 高响应比优先

主要用于作业调度，通常属于非抢占式算法。

响应比公式

$$
\text { 响应比 } = \frac {\text { 等待时间 } + \text { 预计运行时间 }}{\text { 预计运行时间 }}
$$

也可以写成：

$$
\mathrm{响应比} = 1 + \frac {\mathrm{等待时间}}{\mathrm{预计运行时间}}
$$

每次调度时，重新计算所有候选作业的响应比，选择响应比最大的作业。

## 进程和作业的区别：

## 一、作业是什么

作业（Job）是用户提交给计算机、要求系统完成的一项完整任务。

一个作业通常不仅包含程序，还包括：

$$
\text {作业} = \text {程序} + \text {数据} + \text {作业说明书} / \text {控制命令}
$$

例如，在批处理系统中，用户提交“统计学生成绩”这一作业，可能包括：

\- 统计程序;

\- 学生成绩数据；

\- 输入文件位置、输出位置、运行要求等控制命令。

所以，作业强调的是用户要计算机完成什么任务，是从用户和任务的角度描述的概念。

作业提交后，通常先存放在外存的后备队列中，等待操作系统选择。高级调度，也叫作业调度，会从后备队列中选择作业，为它分配必要资源并创建相应进程。王道2027操作系统OCR

## 二、进程是什么

进程（Process）是程序及其数据在计算机上的一次执行过程，是一个动态概念。

从组成上看：

$$
\text {进程实体} = \text {程序段} + \text {数据段} + \mathrm{PCB}
$$

其中PCB是进程控制块，记录：

\- 进程状态;

\- 进程标识符；

\- 资源占用情况；

\- 调度信息等。

因此，进程强调的是：

这个程序现在如何被执行、执行到哪里、占用了什么资源。

## 页表基地址寄存器：

页表基地址寄存器，就是用来保存：

当前正在运行进程的页表在内存中的起始物理地址。

英文常写作 PTBR (Page Table Base Register)。

你可以把它理解成：

页表基地址寄存器 = 当前进程“页表的入口地址”。

它不是页表本身，也不是某个页面的地址，只是告诉 CPU:

“当前进程的页表，要从内存中的哪里开始找。

## 五、栈基址寄存器里到底放什么？

它保存：

当前函数栈帧的基准地址

不同体系结构名称不同，常见名称有：

\- BP: Base Pointer

\- EBP: 32位x86中的基址指针

\- RBP: 64位x86中的基址指针

\- FP: Frame Pointer，帧指针

考研题一般不要求你区分具体名称，统一理解为：

指向当前栈帧某个固定基准位置的寄存器。

## 1. 栈指针会不断变化

程序不断执行：

push
pop
申请局部变量空间
调用其他函数

栈顶位置都会变化，所以SP经常变化。

例如：

```txt

push 一个数据后，SP = 996
再申请16B局部变量后，SP = 980
```

如果始终通过SP寻找局部变量，那么同一个变量相对于SP的偏移量可能不断变化，定位会很麻烦。

## 2. 栈基址相对稳定

进入一个函数后，设置：

```txt
BP = 当前栈帧的基准地址
```




只要该函数还没有返回，BP一般保持相对稳定。

于是可以通过固定偏移访问变量：

```txt

参数 b: BP + 12

```




无论SP如何变化，BP通常不变，所以访问参数和局部变量非常方便。

## C. 在进程处于临界区时不能进行处理机调度——错误

这就是本题最关键的地方。

## 1. 临界区保护的是“临界资源”，不是 CPU

临界区是进程中访问临界资源的一段代码。例如：

```javascript
< C
lock(mutex); // 进入区
count++; // 临界区
unlock(mutex); // 退出区
```

临界区的要求是：

同一时刻，不能有两个进程进入访问同一个临界资源的临界区。

但是，它并没有规定：

处于临界区的进程必须一直占用 CPU，不能被切走。

这两个概念完全不同。

## 2. 处于临界区的进程仍然可能被调度出去

例如 $P_{1}$ 正在临界区中：

```txt
P1获得互斥锁  
P1进入临界区  
P1正在修改共享变量
```

此时恰好发生时钟中断，时间片用完，操作系统完全可以暂停 $P_{1}$ ，调度 $P_{2}$ ：

```txt
CPU: P1 → P2
```

之后有两种情况。

如果 $P_{2}$ 不访问这个临界资源，它可以正常运行。

如果 $P_{2}$ 也想进入同一个临界区，由于锁仍然被 $P_{1}$ 持有， $P_{2}$ 不能进入，只能等待：

```txt
P1：暂时被切走，但仍持有锁  
P2：申请锁失败，等待  
P3：可以继续运行
```

等 $P_{1}$ 再次获得CPU，执行完临界区并释放锁，其他进程才可以进入。

因此：

互斥只保证其他进程不能同时访问同一临界资源，并不保证当前进程不会被CPU调度出去。

所以C错误。

## II. 栈基址寄存器：需要更新

每个进程都有自己的栈，栈中保存：

\- 函数调用关系；

\- 局部变量；

\- 返回地址；

\- 函数参数；

\- 保存的寄存器值等。

例如：

栈基址寄存器保存当前函数栈帧的基准位置。不同进程正在执行不同程序、不同函数，自然有不同的栈现场。因此切换到 $P_{2}$ 时，要恢复 $P_{2}$ 的栈基址：

$$

$$

否则，新进程执行函数时可能错误地访问旧进程的局部变量和返回地址。
