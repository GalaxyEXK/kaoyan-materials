## 按传统BIOS+MBR模型，启动过程大致是：

开机
↓
BIOS 执行
↓
BIOS 硬件自检 POST
↓
BIOS 选择启动设备
↓
BIOS 加载硬盘第 0 扇区的 MBR
↓
MBR 解析分区表，找到活动分区
↓
MBR 加载活动分区的引导扇区 PBR
↓
PBR 加载启动管理器
↓
启动管理器加载操作系统内核
↓
内核初始化
↓
操作系统开始运行

所以这题的关键链路是：

BIOS $\rightarrow$ MBR $\rightarrow$ PBR $\rightarrow$ 启动管理器 $\rightarrow$ OS 内核 $\rightarrow$ 内核初始化

## 并发与并行：

## 1. 一句话区分

并发：同一时间段内，看起来多个任务都在推进。

并行：同一时刻，多个任务真的同时执行。

最核心的区别是：

<table><tr><td>概念</td><td>关键词</td><td>是否真的同时执行</td><td>常见场景</td></tr><tr><td>并发 Concurrency</td><td>同一时间间隔</td><td>不一定</td><td>单核 CPU 上多个进程交替运行</td></tr><tr><td>并行 Parallelism</td><td>同一时刻</td><td>一定</td><td>多核 CPU 上多个进程/线程同时运行</td></tr></table>

王道资料中也明确区分：并发性是多个事件在同一时间间隔内发生；并行性是多个事件在同一时刻发生。在多道程序环境下，单处理器系统中多个程序宏观上像同时运行，但微观上是分时交替执行；若有多个处理器，才能把程序分配到不同处理器上真正并行。 王道2027操作系统\_OCR

## 5. 操作系统为什么要引入并发？

核心目的：提高CPU利用率和系统吞吐量。

如果没有并发，程序A一旦等待I/O，比如等待磁盘读数据，CPU就空闲了。

引入并发后：

<div class="mineru-algorithm" style="white-space: pre-wrap; font-family:monospace;">
进程A等待I/O  
$\downarrow$   
CPU不等它  
$\downarrow$   
操作系统切换到进程B  
$\downarrow$   
CPU继续工作
</div>

所以操作系统通过进程管理、CPU调度、中断机制，让多个进程交替推进，避免CPU长时间空闲。

王道资料中说，在多道程序环境下，操作系统通过调度机制，在一道程序因 I/O 暂停时切换到另一道程序运行，从而实现多道程序交替执行，使 CPU 保持高利用率。☐ 王道2027操作系统\_OCR

## 6. 并发和并行的关系

可以这样记：

<table><tr><td>并发:任务管理问题并行:硬件执行问题</td><td></td></tr></table>

并发强调：操作系统能不能同时管理多个任务，让它们都向前推进。

并行强调：硬件有没有能力在同一时刻执行多个任务。

关系如下：

<table><tr><td>判断</td><td>结论</td></tr><tr><td>单核 CPU 能不能并发?</td><td>能</td></tr><tr><td>单核 CPU 能不能进程级并行?</td><td>不能</td></tr><tr><td>多核 CPU 能不能并行?</td><td>能</td></tr><tr><td>并行是否一定是并发?</td><td>通常认为是</td></tr><tr><td>并发是否一定是并行?</td><td>不一定</td></tr></table>

注意一个细节：虽然单核 CPU 不能让两个进程真正并行，但 CPU 和 I/O 设备之间可以并行。例如 CPU 正在执行进程 B，同时磁盘控制器在为进程 A 读数据，这属于硬件层面的并行。王道中也提到，CPU 与 I/O 设备之间、多个 I/O 设备之间可以实现真正的硬件并行；若要实现进程级别的并行，则需要多核 CPU 或多处理机等硬件支持。☐ 王道2027操作系统\_OCR

## 访管指令:

内核态 $=$ CPU已经在执行操作系统内核程序了。此时权限最高，所以除了“访管指令”这种专门给用户态用来进入内核态的指令外，其他指令都能执行。

## 2. 什么是“访管指令”？

访管指令可以理解成：

用户程序主动请求操作系统服务的一条特殊指令。

也叫：

<table><tr><td>名称</td><td>含义</td></tr><tr><td>访管指令</td><td>访问管理程序/操作系统内核</td></tr><tr><td>陷入指令 / trap 指令</td><td>执行后产生自陷/陷阱</td></tr><tr><td>系统调用指令</td><td>用来发起系统调用</td></tr></table>

## 3. 为什么内核态“除访管指令之外”？

因为访管指令的设计目的就是：从用户态进入内核态。

但内核态已经在内核里了，不需要再“访管”。所以教材说：

在内核态中，CPU 可以执行除访管指令之外的任何指令。

它不是说访管指令很高级、内核态权限不够；而是说：

访管指令是用户态请求内核服务的入口指令，通常规定只能在用户态使用。

内核程序如果要调用另一个内核功能，直接函数调用即可，不需要再通过“访管指令”绕一圈。

## 易混点：

## 4. 最容易混的点

## 易混点1：系统调用不是外中断

系统调用虽然会让CPU从用户态进入内核态，但它不是外设打断CPU，而是程序主动执行Trap/访管指令。

所以：

```txt
系统调用 = 内中断 = 自陷 Trap。
```

## 易混点2：缺页不是外中断

很多人看到“缺页后要访问磁盘”，就误以为它是I/O中断。

其实缺页发生的起点是：CPU执行当前访存指令时发现页不在内存。

所以：

缺页故障 = 内中断 / 异常 / Fault。

后续从磁盘调页完成时，可能再产生一个I/O完成中断，那才是外中断。

易混点3：中断、异常、内中断这些词不同教材口径略有差异

408/王道常用口径:

```txt
外中断：CPU 外部事件  
内中断：CPU 内部事件，也叫异常  
异常：故障 Fault自陷 Trap终止 Abort  
外中断：可屏蔽中断INTR不可屏蔽中断NMI
```

## 自举程序：

这是一个非常基础但核心的概念。简单来说，自举程序（Bootstrap Loader）是计算机通电后执行的第一个程序，它的唯一任务是加载操作系统内核到内存中，并把控制权交给它。

你可以把它理解为计算机的“助产士”——它自己不干活，但负责把真正干活的“操作系统”拉起来。

为了帮你更透彻地理解，我从三个维度来拆解：

## 1. 为什么需要它？（核心痛点）

计算机刚开机时，CPU（中央处理器）处于“空脑”状态，内存里什么都没有。而操作系统通常存放在硬盘里，但硬盘上的文件系统格式复杂，CPU无法直接识别和运行。这就形成了一个死循环：要读硬盘，需要操作系统的驱动；但要有驱动，又得先运行操作系统。自举程序就是为了打破这个死循环而存在的，它直接固化在主板芯片上，不需要任何驱动就能工作。

## 2. 它具体干了什么？（工作流程）

\- 硬件自检（POST）：首先执行开机自检，检查内存、键盘、硬盘等基本硬件是否正常。

\- 定位引导介质：按照BIOS（基本输入输出系统）/UEFI（统一可扩展固件接口）设定的顺序（如U盘→硬盘），找到第一个可启动的设备。

\- 加载引导记录：读取该设备最开头的特定区域（如主引导记录，即MBR，或GUID分区表，即GPT），把里面的启动代码加载到内存。

\- 链式加载：如果主引导记录只包含第一阶段代码，它会去找到分区上的第二阶段引导程序（如Windows的bootmgr或Linux的GRUB）。

\- 加载内核：最终的引导程序会识别文件系统，将操作系统内核（如 vmlinuz）和初始内存盘（initrd）读入内存，然后把CPU控制权交给内核，自此自举程序完成使命，从内存中消失。

## 一、什么是分区表？

你的硬盘可能被分成多个分区，比如：

```txt
硬盘  
分区1：C盘，装Windows  
分区2：D盘，放资料  
分区3：恢复分区  
分区4：其他分区
```

计算机开机时，不能凭感觉知道：

操作系统到底在哪个分区？

所以硬盘前面有一张“表”，记录这些分区的信息，这张表就叫：

分区表

你可以把它理解成硬盘的目录：

<table><tr><td>分区</td><td>起始位置</td><td>大小</td><td>类型</td><td>是否活动</td></tr><tr><td>分区1</td><td>从第2048扇区开始</td><td>100GB</td><td>Windows</td><td>是</td></tr><tr><td>分区2</td><td>后面某处开始</td><td>300GB</td><td>数据分区</td><td>否</td></tr><tr><td>分区3</td><td>后面某处开始</td><td>1GB</td><td>恢复分区</td><td>否</td></tr></table>

其中“是否活动”就很关键。

## 二、什么是活动分区？

活动分区就是被标记为“可以启动操作系统”的分区。

比如你的硬盘里：

<div class="mineru-algorithm" style="white-space: pre-wrap; font-family:monospace;">
C盘：装了Windows $\leftarrow$ 活动分区  
D盘：放电影、资料 $\leftarrow$ 普通数据分区  
恢复分区：系统恢复用 $\leftarrow$ 普通分区
</div>

开机时应该从C盘继续启动，而不是从D盘启动。

所以MBR要做的第一件事就是：

<div class="mineru-algorithm" style="white-space: pre-wrap; font-family:monospace;">
看分区表  
$\downarrow$   
找到哪个分区被标记为活动分区
</div>

这就叫解析分区表。

“解析”不要想复杂，本质就是：

读懂这张表，找到启动分区。

## 三、什么是引导扇区？

扇区是硬盘读写的基本单位。

传统硬盘里，常说一个扇区是512B。你不用纠结大小，先记住：

硬盘不是一个字节一个字节读，而是按扇区读。

每个可启动分区的最开头，也有一个特殊扇区，叫：

## 分区引导扇区

也叫：

PBR, Partition Boot Record, 分区引导记录

它里面放的是下一段引导代码。

所以：

活动分区的引导扇区

活动分区开头的一小段启动程序

## 四、为什么MBR要加载活动分区引导扇区？

因为MBR很小，放不下完整启动逻辑。

传统MBR位于硬盘第一个扇区，空间非常有限，只能干很少的事情：

```txt
1. 检查分区表  
2. 找到活动分区  
3. 把活动分区的引导扇区读入内存  
4. 跳过去执行
```

它不能直接完成：

```txt
加载Windows内核  
加载Linux内核  
显示多系统菜单  
识别复杂文件系统
```

这些事情太复杂，所以要交给下一阶段。

因此，启动过程像接力：

```txt
BIOS
↓
MBR
↓
活动分区引导扇区 PBR
↓
启动管理器
↓
操作系统内核
```

MBR的作用就是：

```txt
找到正确的下一棒，并把控制权交给它。
```

假设你去一个小区找人。

```txt
BIOS：把你送到小区门口

PBR：这栋楼门口的接待员
```

## 问题：

## 问题 1：关于进程与 CPU 利用率

在多道程序系统中，进程数越多，CPU的利用率越高吗？为什么？

结论

不一定。

在多道程序系统中，适当增加进程数，通常会提高 CPU 利用率；但不是进程数越多，CPU 利用率就一定越高。王道资料里 2022 统考相关判断题就把“进程数越多，CPU 的利用率越高”作为错误说法考过。

## 为什么一开始会提高？

多道程序设计的核心思想是：

当一个进程因为 I/O 请求而暂停时，CPU 不空等，马上切换去执行另一个就绪进程。

王道中对多道批处理系统的描述也是：某道程序因 I/O 请求暂停运行时，CPU 立即切换到另一就绪程序继续执行，从而提升吞吐量和资源利用率。王道2027操作系统\_OCR

比如：

情况 CPU 状态
单道程序 程序做 I/O 时，CPU 只能等
多道程序 A 做 I/O 时，CPU 去执行 B/C/D

所以，进程数从1增加到若干个时，CPU空闲时间减少，利用率会上升。

## 为什么不是越多越好？

因为进程数继续增加后，会出现几个问题：

<table><tr><td>问题</td><td>对CPU利用率的影响</td></tr><tr><td>上下文切换变多</td><td>CPU花时间保存/恢复现场,而不是执行用户程序</td></tr><tr><td>调度开销变大</td><td>进程越多,调度管理成本越高</td></tr><tr><td>内存压力变大</td><td>可能频繁缺页,甚至抖动</td></tr><tr><td>Cache/TLB命中率下降</td><td>切换进程后,缓存内容常常失效</td></tr><tr><td>资源竞争严重</td><td>磁盘、打印机、锁等资源竞争变多,进程阻塞增多</td></tr></table>

所以进程数增加到一定程度后，CPU利用率可能趋于饱和，甚至因为系统开销过大而下降。

## 用一句话理解

多道程序设计提高CPU利用率的原因，是用“另一个就绪进程”填补当前进程等待I/O的空闲时间；但如果进程太多，系统管理这些进程本身也要消耗CPU和内存资源，所以不是越多越好。

子程序调用不改变程序的状态，因为子程序调用是编译器可控的流程，而中断不是。下面以程序 if(a==b)为例加以说明。该程序通常包含一条测试指令，以及一条根据标志位决定是否需要跳转来调用子程序的指令。编译器不在这两条指令中间插入任何子程序调用代码，因此标志位不变，但中断随时可能发生，导致标志位改变。具体地说，执行 if(a==b)时，会进行 a-b 操作，并生成相应的标志位，进而根据标志位来判断是否发生跳转。假设刚好在生成相应的标志位后发生了中断，若不保存 PSW 的内容，则后续根据标志位来进行跳转的流程就可能发生错误。但是，若进行了子程序调用，则说明已经根据 a-b 的标志位进行了跳转，此时 PSW 的内容已无意义而无须保存。综上所述，中断处理和子程序调用都有可能使 PSW 的内容发生变化，但中断处理程序执行完返回后，可能需要用到 PSW 原来的内容，子程序执行完返回后，一定不需要用到 PSW 原来的内容，因此选择选项 B。选项 A 都会保存，选项 C 和 D 不一定会保存。

## 3. 为什么 PSW 是答案?

PSW，全称 Program Status Word，程序状态字，里面通常包含：

```txt

```

中断是“随机发生”的。比如程序刚比较完 a == b，标志位刚刚被设置好，还没来得及根据标志位跳转，中断突然来了。

I. 保存被中断程序的中断点 —— 不是 OS，是硬件


## II. 提供中断服务 —— 是 OS

中断服务程序ISR，Interrupt Service Routine，本质上属于操作系统内核或设备驱动的一部分。

例如键盘中断来了：

```txt
键盘控制器发出中断  
CPU进入键盘中断服务程序  
中断服务程序读取键盘数据、放入内核缓冲区
```

真正“处理中断”的是OS/驱动程序，所以II对。


因此要先保存原来的中断屏蔽字，处理完再恢复。

王道解析明确把“保存中断屏蔽字、保存通用寄存器、提供中断服务”归入中断服务程序完成，而中断服务程序属于操作系统内核。 王道2027操作系统\_OCR

## 1. A 为什么错?

A 的问题在于“发生时”三个字。

中断或异常可能发生在用户态，也可能发生在内核态。

```javascript

```

每个系统调用都有一个系统调用号，内核根据系统调用号查系统调用表，然后找到对应的内核服务例程。

流程是：

```txt

内核查系统调用表

```

王道中也明确描述：内核根据系统调用号查询系统调用表，找到对应处理程序入口地址并执行具体服务逻辑。


## 3. C 为什么对?

C说的是：

这句话是对的。

因为中断处理程序属于内核/驱动代码，执行它必须在内核态。硬件响应中断后，会完成状态切换，再跳转到对应处理程序。

王道也说，当CPU运行用户程序时，一旦发生中断或异常，硬件会自动将处理器切换至内核态，并跳转至内核中对应的处理程序。 王道2027操作系统\_OCR

A: 发生时处于内核态 — 错  
C: 处理程序开始执行时处于内核态 — 对

## 题8:

19.【2013 统考真题】计算机开机后，操作系统最终被加载到（）。A.BIOS B.ROM C.EPROM D.RAM

## A. BIOS：不是操作系统

BIOS是主板固件，主要负责开机自检、初始化硬件、选择启动设备、加载MBR等。

王道资料中也明确写到：计算机通电后，CPU从ROM中读取并执行BIOS程序；BIOS完成硬件自检和启动设备选择后，会加载主引导记录MBR。 王道2027操作系统OCR

启动操作系统的前置程序

不是：

操作系统最终所在的位置

## B. ROM：里面放的是固件，不是最终运行的OS

ROM是只读存储器，掉电不丢失，适合存放BIOS/固件程序。

但是操作系统运行时不能主要放在 ROM 中，因为：

1. ROM 通常容量小;

2. ROM不适合频繁读写；

3. 操作系统运行过程中需要大量读写数据结构，比如进程表、页表、缓冲区、内核栈等；

4. CPU执行操作系统时，需要把内核及相关数据结构放到可读写的主存中。

所以 ROM 不是答案。

C. EPROM: 本质上也是一种 ROM

EPROM是Erasable Programmable ROM，可擦除可编程只读存储器。

它也常用于存放固件，而不是作为操作系统最终运行的位置。

所以C错。

RAM是随机存取存储器，也就是我们常说的内存/主存。

开机后，启动程序会把操作系统内核加载到 RAM 中，之后 CPU 才能高效执行操作系统代码，并由操作系统接管计算机资源。

所以D正确。
