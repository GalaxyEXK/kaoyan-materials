## 1.2 盘面与扇区

每个盘面由多个圆环组成，圆环上均匀分布着磁介质（用来存储0/1），每个圆环形成一个盘面的磁道，相邻磁道间的物理距离称为道距。

为了方便地查找数据在磁道中的位置，每个磁道还被分成很多扇区，磁盘的读取以扇区为单位。

从靠近圆心到远离圆心，

每个磁道的物理长度越来越长, 但是每个磁道存储的数据量相同,所以磁道的位密度(单位长度所能存储的比特位数)逐渐变小。

![](第三章 存储系统（下）.docx.assets/c6209b4a86cf55928541e1887bde5438396ad9011711565eb93d3c2c20084439.jpg)

通常每个磁道拥有数量相同的扇区，每个扇区存放存储容量相同的数据。

## 磁盘序列：

RAID 可以提高:

\- 磁盘访问速度；

\- 数据传输率；

\- 可靠性；

\- 可用性。

但它不能提高：

\- 单个磁盘的磁记录密度；

\- 磁盘本身的物理存储密度。

而且 RAID 不一定提高磁盘利用率，比如 RAID 1 镜像会牺牲一半容量。

## DMA:

DMA = Direct Memory Access，直接存储器访问。

在考研408计组里，DMA主要指：外设不经过CPU逐字节搬运数据，而是在DMA控制器的控制下，直接在外设和主存之间传送数据。

## 一、先用一句话理解 DMA

普通方式：

外设 $\rightarrow$ CPU $\rightarrow$ 主存

CPU 亲自搬数据，很累。

DMA 方式:

外设 $\rightarrow$ DMA 控制器 $\rightarrow$ 主存

CPU 只负责“安排任务”，真正搬数据由 DMA 控制器完成。

所以 DMA 的核心作用是:

减少CPU参与，提高大块数据传输效率。

## Cache 的一行:

## 2. 一行 Cache 到底长什么样?

可以画成这样：

```txt
Cache 第 i 行:
标记项——数据区——
| valid | dirty | replacement | Tag | 一个主存块的数据 |
```

其中：

```txt
数据区 = 真正存主存块内容
标记项 = 管理这块数据的说明书
```

你之前老混“Cache块、主存块、数据区”，这里要分清：

```txt
主存块：主存被切成的一块  
Cache行/Cache块：Cache中能放一个主存块的位置  
数据区：Cache行中真正保存主存块内容的部分  
标记项：Cache行中额外保存的管理信息
```

## 标记项：

```txt
Cache 一行通常可以理解成:
```

$$
\mathrm{数据区} + \mathrm{标记项}
$$

标记项里可能包括：

$$
T a g + v a l i d + d i r t y + \mathrm{替换控制位}
$$

它们的作用不一样：

```txt
位 作用
Tag 标记位 判断这一行装的是哪个主存块
valid 有效位 判断这一行数据是否有效
dirty 脏位 判断这一行是否被修改过且未写回主存
替换控制位 判断将来替换时该淘汰哪一行
```

可以记成：

Tag看是谁，valid看有没有，dirty看改没改，替换控制位看该换谁

## 二、Tag 标记位怎么求?

Tag 是这几个里面最重要、最常考的。

CPU 发出一个主存地址，这个地址通常会被拆成：

## 1. 直接映射

$$
\boxed {\text {主存地址} = T a g + \mathrm{Cache行号} + \text {块内地址}}
$$

所以:

$$
\boxed {T a g \text {位数} = \text {主存地址位数} - \mathrm{Cache行号位数} - \text {块内地址位数}}
$$

## 2. 组相联映射

$$
\boxed {\text {主存地址} = T a g + \text {组号} + \text {块内地址}}
$$

所以:

$$
\boxed {T a g \text {位数} = \text {主存地址位数} - \text {组号位数} - \text {块内地址位数}}
$$

## 3. 全相联映射

$$
\text {主存地址} = T a g + \text {块内地址}
$$

所以:

$$
\boxed {T a g \text {位数} = \text {主存地址位数} - \text {块内地址位数}}
$$

全相联没有 Cache 行号，也没有组号，因为任意主存块可以放到 Cache 任意一行。

## 数据区：

Cache 中的数据区，就是这一行真正存放“数据内容”的地方。

可以把 Cache 一行理解成一个“快递柜格子”：

$$
\mathrm{Cache} \text {一行} = \text {数据区} + \text {标记项}
$$

其中：

$$
\mathrm{标记项} = T a g + \mathrm{valid} \mathrm{位} + \mathrm{dirty} \mathrm{位} + \mathrm{替换控制位等}
$$

而数据区存的是：

从主存中复制过来的那一个主存块的实际内容。

## 1. 数据区到底放什么？

假设主存中有一个块：

<table><tr><td>主存块号</td><td>块内内容</td></tr><tr><td>主存块 100</td><td>32B 数据</td></tr></table>

当 CPU 要访问主存块 100，而这个块被调入 Cache 后，Cache 某一行可能变成：

<table><tr><td>Cache 行</td><td>标记项</td><td>数据区</td></tr><tr><td>第 5 行</td><td>Tag、valid、dirty 等</td><td>主存块 100 的 32B 数据</td></tr></table>

所以数据区不是放 Tag，也不是放有效位、脏位，而是放真正要给 CPU 用的内容。

比如 CPU 访问地址 0x12345678，最后真正想读的是这个地址里的某个字节、字、整数或指令。这个内容就在 Cache 行的数据区里。

## 2. 数据区和 Tag 的关系

你图里写的是：

$$
C a c h e \text {一行} = \text {数据区} + \text {标记项}
$$

可以这样记:

Tag 看是谁，数据区放内容。

也就是：

<table><tr><td>部分</td><td>作用</td></tr><tr><td>Tag 标记位</td><td>判断这一行装的是哪个主存块</td></tr><tr><td>valid 有效位</td><td>判断这一行数据是否有效</td></tr><tr><td>dirty 脏位</td><td>判断这一行是否被修改过</td></tr><tr><td>替换控制位</td><td>判断以后替换谁</td></tr><tr><td>数据区</td><td>存放主存块的真实数据副本</td></tr></table>

所以CPU访问Cache时，大致过程是：

1. 根据地址找到可能的 Cache 行/组;

2. 看 valid 位是否为 1;

3. 比较 Tag 是否相等;

4. 如果命中，就从数据区中取出需要的数据；

5. 如果没命中，就从主存调入对应主存块，放到数据区。

## 3. 数据区大小怎么算?

数据区的大小等于:

$$
\mathrm{Cache} \mathrm{块大小}
$$

或者说：

$$
\mathrm{Cache} \text {行的数据区大小} = \text {一个主存块大小}
$$

因为 Cache 和主存之间是以“块”为单位交换数据的。

例如：

主存块大小是32B，那么Cache每一行的数据区就是32B。

如果 Cache 有 64 行，那么总数据区大小是：

$$
6 4 \times 3 2 B = 2 0 4 8 B
$$

这就是通常说的 Cache 容量，也就是 Cache 的数据容量。

注意：很多题里说“Cache 容量”，默认只算数据区大小，不包括 Tag、valid、dirty、替换控制位这些标记项开销。

## 内存管理单元(MMU):

## 概述：

下面按408计组 $+$ 操作系统交叉考点给你把MMU讲透。

## 1. MMU 是什么?

MMU = Memory Management Unit，内存管理单元 / 存储管理部件。

一句话理解：

MMU是CPU访问内存时负责“地址翻译 $+$ 权限检查 $+$ 异常检测”的硬件部件。

CPU执行程序时，程序里看到的地址通常不是主存中的真实物理地址，而是：

\- 逻辑地址 / 虚拟地址 VA

\- 需要被转换成 物理地址 PA

\- 然后才能真正访问 Cache / 主存

王道书里也强调：程序执行时，由CPU中的MMU完成逻辑地址到物理地址的转换，并且转换过程中需要查找页表项、根据有效位判断是否缺页。2027计算机组成原理\_高清带书签版(1)

所以你可以把MMU想成：

CPU 发出一个“虚拟地址”，MMU 负责把它翻译成“物理地址”。

## 2. MMU 在哪里?

一般说法：

MMU 通常集成在 CPU 内部，位于 CPU 核心和存储系统之间。

逻辑关系可以这样看：

```txt
CPU 核心产生虚拟地址 VA
↓
MMU
地址转换 + 权限检查
↓
得到物理地址 PA
↓
访问 Cache / 主存
```

注意，MMU 不是主存的一部分，也不是页表本身。它是一个硬件功能部件。

## 3. 为什么需要 MMU?

因为现代系统大多使用虚拟存储器。

没有MMU时，程序直接使用物理地址，会有几个问题：

1. 程序必须知道真实内存位置，不方便。

2. 多个程序可能互相覆盖内存，不安全。

3. 程序大小受物理内存限制。

4. 无法方便地实现虚拟内存、分页、内存保护、共享内存等机制。

有了MMU后：

```txt
每个进程都以为自己有一片连续、独立的虚拟地址空间  
但实际物理内存可以是分散的  
甚至有些页面暂时在外存中
```

这就是虚拟存储器的基础。408大纲中，计组的“存储器层次结构”明确要求掌握虚拟存储器、页式虚拟存储器、页表、地址转换、TLB；操作系统大纲中也要求掌握逻辑地址空间与物理地址空间、地址变换、内存保护、虚拟内存管理等内容。 408大纲

## 4. MMU 最核心的工作：虚拟地址 → 物理地址

页式虚拟存储中，虚拟地址通常拆成两部分：

```txt
虚拟地址 VA = 虚拟页号 VPN + 页内偏移 Offset
```

![](第三章 存储系统（下）.docx.assets/d48e65aff7c57b777171266b133ce266f5ad901c9a0955cd7f3ac90f2d3b5309.jpg)

物理地址也拆成两部分：

```txt
物理地址 PA = 物理页框号 PFN + 页内偏移 Offset
```

重点来了：

页内偏移不变，MMU主要负责把虚拟页号VPN翻译成物理页框号PFN。

因为一个虚拟页和一个物理页框大小相同，比如都是4KB，所以页内位置不会变。

## 7. MMU 会检查什么?

MMU 地址转换过程中主要检查：

1. TLB 是否命中

2. 页表项是否有效

3. 是否缺页

4. 是否访问越权

5. 读写权限是否允许

比如：

\- 只读页面被写入 $\rightarrow$ 访问越权

\- 用户态访问内核页 $\rightarrow$ 访问越权

\- 页面不在主存 $\rightarrow$ 缺页异常

\- TLB 中没有对应项 $\rightarrow$ TLB 缺失

2024 统考真题就考过：在 MMU 地址转换过程中检测的有访问越权、页面缺失、TLB 缺失；Cache 缺失不是 MMU 地址转换过程中检测的，因为 Cache 访问是在得到物理地址之后进行的。

## 5. MMU、页表、TLB 三者关系

## 2) TLB 是什么?

TLB = Translation Lookaside Buffer，快表。

它是页表项的高速缓存。

你可以理解为：

页表：完整地址翻译表，放在主存中，慢

TLB：最近用过的一小部分页表项，放在高速硬件中，快

所以：

TLB 是 MMU 加速地址转换用的小 Cache。

王道中也强调，TLB 的内容是页表的一部分副本，Cache 的内容是主存的一部分副本。

## 3）MMU 是什么？

MMU 是执行地址转换的硬件。

它会：

```txt
先查TLB  
TLB不命中再查页表  
查到后得到物理页框号  
再拼接页内偏移形成物理地址
```

所以三者关系是：

```txt
MMU：负责翻译地址的硬件  
TLB：MMU内/旁边的高速页表缓存  
页表：操作系统维护的完整映射表
```

一句话区分：

MMU是“翻译器”，TLB是“翻译缓存”，页表是“翻译字典”。

比如页大小是 4KB，则 Offset 占 12 位。

MMU 先用虚拟页号 VPN 查 TLB。

## 情况 A: TLB 命中

说明最近访问过这个虚拟页，TLB 中已有对应页表项。

```txt
VPN → PFN
```

然后：

物理地址 PA = PFN + Offset

地址转换很快完成。

说明 TLB 中没有这个虚拟页对应的翻译结果。

VPN → 页表 → 页表项 PTE

```txt
PA = PFN + Offset
```

同时可能把这个页表项装入 TLB，方便下次访问。

## 1. 先回忆：Tag 到底是什么？

Tag = 标记位 = 用来判断 Cache 里这个块到底是不是我要找的那个主存块。

你可以这样理解：

CPU 给出一个主存地址，Cache 要做三件事：

1. 先定位去哪找：看行号或组号。

2. 再判断是不是它：比较 Tag。

3. 最后取块内哪个字节/字：看块内地址。

所以：

行号/组号负责“去哪一行/哪一组找”；

Tag 负责“确认这一行/这一组里放的是不是目标主存块”；

块内地址负责“命中后取块内哪个位置的数据”。

## 页式虚拟存储器采用全相联映射

□ 每个虚拟页可以存放到主存中的任何一个空闲的物理页。

对于每个进程，都需要建立进程中各个虚拟页与所存放的主存物理页或磁盘上存储位置之间的关系，通常采用页表（Page Table，PT）来记录这种对应关系。

## 页表：

页表常驻于内存

![](第三章 存储系统（下）.docx.assets/977133f835bf2b9b6a79018427dfab65ea11068af11fb5e2846fb5d2660ff806.jpg)

☐ ☐

这个“内存”指的是主存（也叫 RAM，随机存取存储器），不是辅存（如硬盘、SSD）。

具体解释一下:

1. 页表的作用：页表用于记录虚拟地址到物理地址的映射关系。CPU 的内存管理单元（MMU）在把虚拟地址转换为物理地址时，需要查页表。

2. 为什么必须常驻主存：每次访问内存（取指令、读数据）都可能涉及地址转换，如果页表放在辅存（硬盘/SSD）上，每次查表都需要慢几个数量级的 I/O 操作，性能会崩溃。所以页表必须放在 CPU 能直接快速访问的主存中。

3. “常驻”的含义：整个进程的页表通常一直分配在主存里，不会被换出到辅存（虽然部分页表结构如“页目录”等也是存在主存）。不过请注意：页表本身占用的主存页面，通常不会被操作系统换出，因为那会导致地址转换无法完成（死锁风险）。例外的是某些大型页表（如64位系统）可能采用多级页表+虚拟化页表的方式，但最顶层的根页表永远在主存。

页表就是：记录“虚拟页号 $\rightarrow$ 物理页号”的映射表。

你可以把它理解成一本“地址翻译字典”：

CPU 给出的是虚拟地址，MMU 要靠页表把它翻译成物理地址。

## 1. 页表到底干什么？

页式虚拟存储器中，程序看到的是虚拟地址：

$$
V A = \mathrm{虚拟页号} + \mathrm{页内偏移}
$$

但主存真正用的是物理地址：

$$
P A = \mathrm{物理页号} + \mathrm{页内偏移}
$$

所以问题来了：

虚拟页号怎么知道对应哪个物理页号？

答案就是：查页表。

例如图中：

<table><tr><td>虚拟页</td><td>对应物理页</td></tr><tr><td> $VP_{2}$ </td><td> $PP_{0}$ </td></tr><tr><td> $VP_{3}$ </td><td> $PP_{1}$ </td></tr><tr><td> $VP_{5}$ </td><td> $PP_{2}$ </td></tr><tr><td> $VP_{7}$ </td><td> $PP_{3}$ </td></tr></table>

这张对应关系表，就是页表的核心内容。

## 2. 页表和页表项的关系

这个关系非常重要：

页表 = 很多页表项组成的表。

页表项 $=$ 页表中的一行。

类比:

<table><tr><td>概念</td><td>类比</td></tr><tr><td>页表</td><td>一本通讯录</td></tr><tr><td>页表项</td><td>通讯录里的一条联系人记录</td></tr><tr><td>虚拟页号</td><td>要查的名字</td></tr><tr><td>物理页号</td><td>查出来的电话号码</td></tr></table>

所以你问“页表是什么”，它就是一张表；

你前面问“页表项怎么看”，页表项就是这张表里的每一行。

## 3. 查页表的过程

假设 CPU 给出虚拟地址：

$$
V A = V P _ {5} + \mathrm{页内偏移} d
$$

MMU 做这几步:

第一步，拆虚拟地址：

$$
V A = \mathrm{虚拟页号} V P _ {5} + \mathrm{页内偏移} d
$$

第二步，用虚拟页号查页表：

$$
V P _ {5} \rightarrow P P _ {2}
$$

第三步，拼物理地址：

$$
P A = P P _ {2} + \mathrm{页内偏移} d
$$

注意：查表只查虚拟页号，不查页内偏移。

页内偏移原封不动保留下来。

## 4. 页表存在哪里？

页表本身通常放在主存中，由操作系统管理。

CPU/MMU 里面会有一个寄存器保存页表的起始地址，这类寄存器常叫：

$$
\mathrm{页表基址寄存器}
$$

也就是告诉 MMU:

当前进程的页表从主存哪里开始。

所以地址转换大致是：

$$
\mathrm{虚拟地址} \rightarrow M M U \rightarrow \mathrm{查页表} \rightarrow \mathrm{物理地址}
$$

## 5. 页表是不是只有一张？

对单个进程来说，可以理解为“有自己的页表”。

因为不同进程的虚拟地址空间彼此独立。

比如进程A和进程B都可能访问虚拟地址0x1000，但是它们对应的物理地址可以完全不同。

所以：

每个进程通常有自己的页表。

这就是为什么虚拟内存可以实现进程隔离。

## 6. 页表里一定有物理页号吗？

不一定。

## 页表基址寄存器：

页表基址寄存器，英文常叫PTBR：PageTableBaseRegister。你可以先把它理解成一句话：

页表基址寄存器保存“当前进程的页表在主存中的起始地址”。

408 大纲里，页式虚拟存储器要求掌握“页表、地址转换、TLB（快表）”这些内容，所以页表基址寄存器就是为了支持“根据虚拟页号找到页表项”服务的。☐ 408大纲

## 1. 为什么需要页表基址寄存器？

每个进程都有自己的虚拟地址空间，因此通常也有自己的页表。

CPU 执行某个进程时，发出的地址是虚拟地址，比如：

$$
\text { 虚拟地址 } = \text { 虚拟页号 } + \text { 页内偏移 }
$$

但是CPU最终访问主存需要的是物理地址，所以必须查页表，把虚拟页号转换成物理页框号。

问题来了：

页表放在主存哪里？

这个位置就由页表基址寄存器告诉MMU。

## 2. 地址转换时它怎么用？

假设：

\- 页表基址寄存器PTBR中存的是页表起始地址；

\- 虚拟地址被分成：虚拟页号 $p$ 和页内偏移 $d$ ;

\- 每个页表项大小为 $s$ 字节。

那么第 $p$ 号虚拟页对应的页表项地址是：

$$
\text { 页表项地址 } = \text { 页表基址 } + p \times \text { 页表项大小 }
$$

也就是：

$$
P T E \text {地址} = P T B R + p \times s
$$

找到页表项后，取出里面的物理页框号 $f$ ，再和页内偏移 $d$ 拼接，得到物理地址：

$$
\mathrm{物理地址} = \mathrm{物理页框号} \times \mathrm{页面大小} + \mathrm{页内偏移}
$$

王道书里地址转换的基本过程也是：先取出逻辑页号，查页表得到页框号，再将页框号与页内偏移量拼接得到物理地址。 2027计算机组成原理\_高清带书签版(1)

## 5. 它和TLB/快表有什么关系？

正常查页表比较慢，因为页表在主存中。一次访存指令可能要：

1. 先访问主存查页表；

2. 再访问主存取数据。

所以引入TLB，也叫快表。TLB保存最近用过的一部分页表项。

地址转换时一般是：

1. CPU 给出虚拟地址;

2. MMU 先用虚拟页号查 TLB;

3. 如果 TLB 命中，直接得到页框号，不用访问主存中的页表；

4. 如果 TLB 未命中，再用页表基址寄存器找到页表，在主存中查页表项；

5. 查到后得到页框号，形成物理地址。

所以:

TLB命中时，通常不需要用页表基址寄存器去主存查页表；TLB未命中时，才需要通过页表基址寄存器定位页表。

王道书中也强调：TLB是页表的一部分副本，TLB命中时能直接进行转换；TLB、Page、Cache的命中关系是408常考点。2027计算机组成原理\_高清带书签版(1)

## 6. 进程切换时它会变吗？

会变。

因为不同进程有不同页表。操作系统切换进程时，除了保存/恢复 PC、通用寄存器等，还要把页表基址寄存器改成新进程页表的起始地址。

比如：

\- 进程 A 的页表从主存 10000 开始;

\- 进程 B 的页表从主存 50000 开始。

CPU 执行 A 时:

$$
P T B R = 1 0 0 0 0
$$

切换到 B 时:

$$
P T B R = 5 0 0 0 0
$$

这样，同一个虚拟地址，在不同进程中可以映射到不同的物理地址。

这也是虚拟存储器能实现“每个进程都有独立地址空间”的关键。

## 7.408 常考角度

页表基址寄存器本身一般不会单独考很难，常混在地址转换题里考。

你要会这几个判断：

第一，页表基址寄存器中存的是页表起始地址，不是页框号，不是页表项内容。

第二，虚拟页号用于查页表，页内偏移不参与查页表。

第三，页内偏移在虚拟地址和物理地址中通常不变，因为页面大小和页框大小相同。

$$
\text {第四，页表项地址} = \text {页表基址} + \text {虚拟页号} \times \text {页表项长度。}
$$

$$
\text {第五，物理地址} = \text {页框号} \times \text {页面大小} + \text {页内偏移，或者说“页框号与页内偏移拼接”。}
$$

第六，TLB命中时不必访问主存页表；TLB未命中时才通过页表基址寄存器找页表。

页内偏移的位数决定页面大小。

页内偏移的取值范围等于一个页面内所有字节的位置范围。

## 3. 页内偏移和页面大小的关系

假设页面大小是4KB。

因为：

$$
4 K B = 4 0 9 6 B = 2 ^ {1 2} B
$$

所以页内偏移需要 12 位。

也就是说：

$$
\mathrm{页内偏移位数} = \log_ {2} \mathrm{页面大小}
$$

如果页面大小是 4KB，那么：

<table><tr><td>项目</td><td>值</td></tr><tr><td>页面大小</td><td>4KB = 4096B</td></tr><tr><td>页内偏移位数</td><td>12位</td></tr><tr><td>页内偏移取值范围</td><td>0 ~ 4095</td></tr></table>

所以你要记住：

页内偏移不是页面大小，而是页面内部的地址。

页内偏移的位数可以推出页面大小。

## 1. 先抓住核心：什么叫“缺页”？

CPU发出的是虚拟地址VA。

虚拟地址一般被分成：

```txt
虚拟页号VPN + 页内偏移
```

MMU 拿虚拟页号去查页表，想知道：

```txt
这个虚拟页现在在不在主存？如果在主存，它对应哪个物理页框？
```

页表项里通常有这些信息：

```txt
有效位 / 存在位  
物理页号 / 页框号  
访问权限  
脏位  
访问位
```

其中：

<div class="mineru-algorithm" style="white-space: pre-wrap; font-family:monospace;">
有效位 $= 1$ ：该虚拟页已经在主存中  
有效位 $= 0$ ：该虚拟页不在主存中，发生缺页
</div>

所以图中的第4步：

若页表项中的有效位为0，则说明所访问的页不在主存中，MMU触发缺页异常。

这就是缺页异常 page fault。

## 第四步：发生缺页异常

这里的“脏位”不是说页面脏了，而是说：

## 脏位 $= 0$ ：主存里的页面和磁盘里的页面一样

比如某页面 P 原来在磁盘中:

磁盘中的页面 P: 100

操作系统把它调入主存：

主存中的页面 P: 100

磁盘中的页面 P: 100

程序只是读它，没有修改它：

读P

那么主存和磁盘仍然一样：

主存中的页面 P: 100

磁盘中的页面 P: 100

这时如果要把 P 这个页框腾出来，没必要再把它写回磁盘。

因为磁盘中已经有一份完全一样的内容。

所以可以直接丢弃主存中的副本：

主存中的 P: 丢弃

磁盘中的 P: 还在

这里的“丢弃”不是说数据没了，而是说：

只丢弃主存中的副本，磁盘上的原始页面还在。

以后如果这个页面又被访问，再从磁盘重新调入即可。

## 脏位 $= 1$ ：主存里的页面比磁盘里的新

还是页面 P，原来磁盘中是：

```txt
磁盘中的页面 P: 100
```

调入主存:

主存中的页面 P: 100  
磁盘中的页面 P: 100

然后 CPU 执行写操作:

```rust
<//> C
P = 200;
```

这时变成：

主存中的页面 P: 200  
磁盘中的页面 P: 100

主存中的内容被修改了，磁盘中的旧副本已经过时。

所以页表项中的脏位会变成：

脏位 = 1

如果这时候直接丢弃主存页面，就会发生严重错误：

```txt
主存中的P：200被丢弃磁盘中的P：还停留在100
```

那程序对P的修改就丢失了。

所以必须先把主存中的新内容写回磁盘：

<div class="mineru-algorithm" style="white-space: pre-wrap; font-family:monospace;">
主存中的P：200 $\rightarrow$ 写回磁盘磁盘中的P：200
</div>

↓

写回完成后，这个主存页框才能被腾出来。

## 这就是图中说的：

如果该页面的脏位为 1，则把该页面调出到磁盘，否则直接丢弃。

## 4. 一句话理解脏位

你可以这样记：

脏位 $= \theta$ ：没改过，磁盘已有正确副本，可以直接扔掉主存副本。

脏位 = 1：改过，主存是最新版，必须先写回磁盘，不能直接扔。

## 更通俗一点:

脏位 = 0：主存这份只是“复印件”，原件还在磁盘，扔了没事。

脏位 = 1：主存这份已经被你改成“新版”，磁盘还是旧版，扔了就丢修改。

## 5. 注意：这里“调出”的是谁？

这是一个非常容易混的点。

缺页时有两个页面：

1. 缺失页面：CPU 想访问，但不在主存，需要从磁盘调入

2. 被替换页面：主存满了，被选中让出页框

图中“脏位为 1 就调出，否则丢弃”，说的是：

被替换页面

不是 CPU 当前想访问的那个缺失页面。

完整过程是：

CPU 想访问页面 A

A 不在主存 $\rightarrow$ 缺页

主存满了 $\rightarrow$ 选页面B牺牲

检查B的脏位

如果B脏位 $= 1$ ，把B写回磁盘

如果B脏位 $= \theta$ ，直接丢弃B的主存副本

然后把A从磁盘调入B原来占用的页框

更新A的页表项

重新执行刚才那条导致缺页的指令

## 6. 第 6 步：从磁盘调入新页面，并更新页表

被替换页面处理完以后，系统把缺失的页面从磁盘读入主存。

比如 CPU 想访问虚拟页 A，原来：

A 不在主存

缺页处理后：

A 被从磁盘调入主存页框 5

于是页表项要改成:

有效位 = 1
物理页号 = 5
脏位 = 0
访问位 = 1

为什么刚调入时脏位通常是 0?

因为刚从磁盘读进来，还没被 CPU 修改，主存和磁盘内容一致。

## 7. 第 7 步：返回原进程，重新执行出错指令

缺页异常处理完后，操作系统返回原进程。

刚才导致缺页的那条指令会重新执行。

第一次执行:

访问 $\mathsf{A}\to \mathsf{A}$ 不在主存 $\rightarrow$ 缺页

处理后 A 已经在主存。

第二次执行：

访问 $\mathsf{A}\rightarrow$ 页表有效位 $= 1\to$ 正常访问

所以图中说:

之前引起缺页的指令会重新启动，这次执行就不会缺页了。

## 2. 采用虚拟存储后，多了一步地址转换

有虚拟存储后，CPU给出的不是物理地址，而是虚拟地址：

```txt
CPU给出虚拟地址VA  
↓  
MMU根据页表/TLB转换成物理地址PA  
↓  
再根据物理地址访问Cache/主存
```

也就是说，真正访问数据之前，先要解决一个问题：

这个虚拟页现在对应哪个物理页框？

这就需要查页表或TLB。

所以虚拟存储会影响性能的第一层原因是：

每次访存都可能多出“地址转换”的开销。

## 7. 为什么还要用虚拟存储？

你可能会想：既然影响性能，为什么还要用？

因为虚拟存储的主要目的不是“让单次访存更快”，而是：

1. 扩大程序可使用的地址空间

2. 让程序不用一次性全部装入主存

3. 支持多道程序运行

4. 实现进程隔离和内存保护

5. 简化程序装入和地址管理

它牺牲了一部分地址转换开销，换来了更大的容量、更好的管理和更强的系统功能。

所以准确说：

虚拟存储不是单纯为了加快访存速度；

它主要是为了解决主存容量和内存管理问题。

■为了加快MMU进行虚拟地址到物理地址转换的速度，现代处理器内部都包含有一个转换后备缓冲器（Translation Lookaside Buffer，TLB），专门用于缓存经常访问的页表项。

TLB（Translation Lookaside Buffer，页表缓存）是CPU中用于加速虚拟地址到物理地址转换的硬件缓存。其典型条目包含以下核心字段：

1. 虚拟页号（VPN，Virtual Page Number）：作为TLB的标签（Tag），用于匹配传入的虚拟地址。

2. 物理页帧号（PFN，Physical Frame Number）：VPN对应的物理内存页框号。命中后与虚拟地址的页内偏移拼接成物理地址。

3. 有效位（Valid Bit）：表示该TLB条目是否有效。上下文切换、页表修改后可能清空此位。

4. 访问权限位（Protection/Permission Bits）：控制读写执行权限（如 R/W/X），防止非法访问。常见形式为用户/内核态权限（U/S 位，用于分离用户态与内核态访问）。

5. 脏位（Dirty Bit）：表示对应物理页是否被写过。用于指导页面换出时是否需要写回磁盘（若未脏则可丢弃）。

6. 访问位（Accessed/Use Bit）：记录该页是否被读/写过。操作系统可用其实现页面置换算法（如LRU近似）或页面迁移。

7. 地址空间标识符（ASID，Address Space Identifier）：用于区分不同进程的TLB条目，避免每次进程切换都清空TLB，提高命中率。

8. 全局位（Global Bit）：指示该条目是否对所有进程可见（如内核共享页）。如果置位，TLB查找时忽略ASID匹配检查。

## 一、先记总公式

设：

\- 虚拟地址位数 $= \mathrm{m}$

\- 页面大小 $= 2^{\mathrm{d}} \mathbf{B}$ , 则页内偏移 $= \mathbf{d}$ 位

\- TLB 表项总数 = E

\- TLB为r路组相联

则：

$$
\mathrm{虚页号位数} = m - d
$$

$$
T L B \text {组数} = \frac {E}{r}
$$

$$
T L B \mathrm{组号位数} = \log_ {2} (\frac {E}{r})
$$

所以：

$$
T L B \text {标记字段位数} = \text {虚页号位数} - T L B \text {组号位数}
$$

也就是：

$$
T L B \text {标记字段位数} = m - d - \log_ {2} (\frac {E}{r})
$$

## 六、最容易错的点

不要拿物理地址来算TLB标记字段。

TLB 的标记字段对应的是：

段式虚拟存储器：

## 3.6.3 段式虚拟存储器 $^{①}$

段式虚拟存储器中的段是按程序的逻辑结构划分的，各个段的长度因程序而异。虚拟地址分为两部分：段号和段内地址。虚拟地址到物理地址的变换由段表实现。段表是程序的逻辑段与其在主存中存放位置的对照表，每行记录某个段的段号、有效位、段起点和段长等信息。由于段的长度可变，段表中必须给出各段的起始地址与段长。

![](第三章 存储系统（下）.docx.assets/227612bf10ff012ce95abd13c912a6d12d5948c29e0f85e5349e0adb0ea40f18.jpg)  
图3.31 段式虚拟存储器的地址变换过程

CPU 根据虚拟地址访存时，首先从虚拟地址中提取段号，并根据段表基地址找到对应的段表项。然后检查该段表项的有效位：若为 1，表示该段已调入主存；若为 0，表示该段不在主存中。当该段已调入主存时，从段表读出其在主存中的起始地址，与段内地址相加，得到对应的物理地址。段式虚拟存储器的地址变换过程如图 3.31 所示。

由于段是程序逻辑结构所决定的独立部分，因此分段对程序员来说是不透明的；而分页对程序员是透明的，程序员编写程序时无须关心程序如何分页。

段式虚拟存储器的优点是：段的边界与程序的自然逻辑边界一致，具有良好的逻辑独立性，便于程序的编译、管理、修改和保护，也易于实现多道程序间的段共享。缺点是：段长度可变，主存分配困难，段间容易产生外部碎片，难以有效利用，造成存储空间浪费。

## 段页式存储器：

## 3.6.4 段页式虚拟存储器

在段页式虚拟存储器中，程序先按逻辑结构分段，每段再划分为固定大小的页，主存空间也划分为大小相等的页，程序对主存的调入和调出仍以页为基本交换单位。每个程序对应一个段表，每段对应一个页表。虚拟地址由段号、段内页号和页内地址三部分组成。CPU根据虚地址访存时，首先用段号查找段表，获得该段对应的页表起始地址；接着以段内页号为索引访问页表，取出实页号；最后将实页号与页内地址拼接，形成物理地址。

段页式虚拟存储器的优点是兼具页式和段式的优点，既支持按段进行共享和保护，又避免了段式存储的外部碎片问题。缺点是在地址变换过程中需要两次查表，系统开销较大。

## 虚拟存储器与 cache 的比较:

## 3.6.5 虚拟存储器与 Cache 的比较

## 考点追踪 虚拟存储器与 Cache 的比较（2024）

虚拟存储器与 Cache 既有相同之处，又有不同之处。

## 1. 相同之处

1）最终目标都是提高系统性能，两者都体现了容量、速度、价格的梯度。

2）都把数据划分为小信息块作为基本交换单位，虚拟存储器的页通常比 Cache 块大得多。

3）都涉及地址映射、替换算法和更新策略等问题。

4）都基于局部性原理，采用“快速缓存”思想，将活跃数据放在高速部件中。

## 2. 不同之处

1）Cache 主要解决 CPU 与主存之间的速度差异，而虚拟存储器为了解决主存容量。

2）Cache完全由硬件实现，对所有程序员透明；虚拟存储器由操作系统和硬件共同实现，对应用程序员透明，但其管理机制对操作系统开发者不透明。

考点追踪 ➤ Cache 缺失和缺页的处理开销对比（2016）

3）不命中时的性能影响不同：Cache 不命中需访问主存，延迟增加数十倍；而虚拟存储系统缺页需访问磁盘，延迟增加可达十万倍，对系统性能影响更为严重。

4）CPU可直接访问Cache和主存，Cache不命中时，硬件自动从主存取数据并装入Cache。辅存与CPU无直接通路，缺页时必须先将数据从辅存调入主存，之后CPU才能访问。

## 替换控制位：

## 一、替换控制位是什么？

替换控制位就是 Cache 为了执行“替换算法”而额外保存的状态信息。

Cache 发生未命中时，如果目标位置已经满了，就要决定：

到底踢掉哪一个 Cache 块?

为了做这个决定，Cache 需要记录一些辅助信息，比如：

\- 哪一块最久没用;

\- 哪一块最早进入 Cache;

\- 哪一块最近刚用过;

\- 当前这一组下一次该替换哪一路。

这些辅助信息对应的 bit，就叫替换控制位。

## 二、为什么需要替换控制位？

先看 Cache 访问过程。

CPU 给出一个主存地址，Cache 会拆成：

$$
\mathrm{标记} T a g + \mathrm{组号/行号} + \mathrm{块内地址}
$$

如果命中，直接读写。

如果未命中，就要把主存块调入 Cache。

这时有两种情况：

## 1. 目标位置还有空行

那直接放进去，不需要替换。

## 2. 目标位置已经满了

这时就要选择一个旧块踢出去。

问题来了：

选谁？

这个“选谁”的规则就是替换算法。

比如：

\- FIFO：替换最早进入 Cache 的块；

\- LRU：替换最近最久未使用的块；

\- Random: 随机替换;

而为了执行这些算法，Cache必须记录一些状态，这就是替换控制位。

\- LFU：替换使用次数最少的块。

## 块内地址：

块内地址，也叫：

块内偏移量 / 块内位移 / offset

它表示：在一个“块”里面，具体找第几个字节。

## 1. 先记住一句话

主存地址可以拆成：

$$
\text { 主存地址 } = \text { 主存块号 } + \text { 块内地址 }
$$

也就是：

先找到是哪一块，再找到这一块里面的第几个字节。

就像一本书：

<table><tr><td>地址结构</td><td>类比</td></tr><tr><td>主存块号</td><td>第几页</td></tr><tr><td>块内地址</td><td>这一页里的第几个字/第几个位置</td></tr></table>

## 2. 为什么需要块内地址？

Cache和主存之间交换数据时，不是一个字节一个字节交换，而是一块一块交换。

比如：

每个主存块大小为 32B

意思是：一个块里面有 32 个字节。

那么当 CPU 给出一个地址时，系统要知道：

1. 这个地址属于哪一个主存块；

2. 这个地址是该块内部的第几个字节。

第二部分就是块内地址。

## 3. 块内地址的位数怎么算？

核心公式:

$$
\mathrm{块内地址位数} = \log_ {2} (\mathrm{块大小})
$$

前提：块大小按字节B计算。

例如：

<table><tr><td>块大小</td><td>块内有多少个字节</td><td>块内地址位数</td></tr><tr><td>4B</td><td>4个字节</td><td> $\log_{2} 4 = 2$ 位</td></tr><tr><td>8B</td><td>8个字节</td><td> $\log_{2} 8 = 3$ 位</td></tr><tr><td>16B</td><td>16个字节</td><td> $\log_{2} 16 = 4$ 位</td></tr><tr><td>32B</td><td>32个字节</td><td> $\log_{2} 32 = 5$ 位</td></tr><tr><td>64B</td><td>64个字节</td><td> $\log_{2} 64 = 6$ 位</td></tr></table>

所以如果题目说：

块大小为 32B

那么块内地址是：

$$
\log_ {2} 3 2 = 5
$$

所以是5位，不是8位。

想象一个图书馆：

## 2. 回到计算机：技术定义

在CPU访问内存时，地址被分成三部分（以组相联/直接映射为例）：

\- 块内地址：地址的最低几位（低位）。

\- 作用：告诉CPU，当整个块已经被调入Cache后，我要找的数据在这个块的开头偏移多少字节。

\- 位数的决定：块大小 $= 2$ 块内地址位数字节。

## 2. 为什么要有“页”

真实情况是：程序以为自己有一大块连续内存，比如从地址0开始一直用到很大的地址。

但实际主存很小，不可能把所有程序全部放进去。于是系统引入虚拟存储器：

程序看到的是“虚拟地址空间”，实际运行时由系统把需要的部分放入主存，不需要的部分暂时放在外存。

## 2. 虚拟地址是什么？

虚拟地址，也叫逻辑地址，是程序运行时看到、使用的地址。

比如一个进程认为自己有一大片连续空间：

```txt
0x00000000
0x00000004
0x00000008
...
```

但这只是“程序视角”。实际上，这些地址对应的内容可能分散在主存不同位置，甚至有些页面暂时还在磁盘上，没有调入主存。

所以虚拟地址的本质是：

程序认为自己正在访问的地址

它不一定直接等于主存中的真实地址。

## 3. 物理地址是什么？

物理地址，也叫实地址，是主存储器中真实存储单元的地址。

也就是内存条实际被访问的位置。

比如虚拟地址：

虚拟地址：0x12345

经过地址转换后，可能变成：

物理地址：0x8A345

CPU 最终访问主存时，用的是这个物理地址。

## 4. 为什么要有虚拟地址？

如果程序直接使用物理地址，会有很多麻烦。

第一，多个程序同时运行时，容易互相干扰。比如程序A和程序B都想用地址0x1000，那到底给谁？

第二，程序必须知道自己被放在主存哪里，这很不方便。用了虚拟地址后，程序只管使用自己的地址空间，具体放到主存哪里由操作系统安排。

第三，可以让程序感觉自己拥有很大的空间。即使物理内存只有 8GB，程序也可以看到更大的虚拟地址空间，只是暂时不用的部分可以放在磁盘里。

所以虚拟地址的作用主要是：

```txt
地址空间隔离  
内存保护  
程序重定位  
扩大程序可用地址空间  
支持虚拟内存
```

## 2. 地址转换时它怎么用？

假设：

\- 页表基址寄存器PTBR中存的是页表起始地址；

\- 虚拟地址被分成：虚拟页号 $p$ 和页内偏移 $d$ ;

\- 每个页表项大小为 $s$ 字节。

那么第 $p$ 号虚拟页对应的页表项地址是：

$$
\mathrm{页表项地址} = \mathrm{页表基址} + p \times \mathrm{页表项大小}
$$

也就是：

$$
P T E \text {地址} = P T B R + p \times s
$$

找到页表项后，取出里面的物理页框号 $f$ ，再和页内偏移 $d$ 拼接，得到物理地址：

$$
\text { 物理地址 } = \text { 物理页框号 } \times \text { 页面大小 } + \text { 页内偏移 }
$$

## 1. 缺页处理通常要到磁盘中读取数据

是的，缺页处理通常需要到磁盘读取数据。

结合你图中的流程，完整的过程是这样的：

## 1. 两个概念的区别

\- TLB缺失：TLB（快表）里没找到地址转换条目。这时硬件或操作系统去内存的页表里查找。如果页表里有记录（有效位为1），就把条目加载到TLB，不需要访问磁盘。

\- 缺页：去内存的页表里查找时，发现该页的有效位为0（或不在内存中）。这意味着数据确实不在物理内存里，这时才需要去磁盘读取。

所以，你图中圈出的“TLB缺失”下一步是查内存中的页表。只有当页表也显示“缺失”时（即真正的缺页），才会触发磁盘I/O。

## 2. 缺页处理的确需要读磁盘

当发生真正的缺页（Page Fault）时，步骤如下：

1. 陷入操作系统内核，保存当前进程的上下文。

2. 从磁盘找到缺失的页面（磁盘里的交换区或可执行文件）。

3. 在物理内存中找一个空闲页框（如果没有，需要先换出某个旧页到磁盘）。

4. 从磁盘读取缺失的页面到该物理内存页框（这个过程很慢，通常是纳秒级 vs 毫秒级的差距）。

5. 更新页表，将物理页框号填入，并设置有效位=1。

6. 重新执行导致缺页的指令，这时TLB可能还会缺失一次，但页表已经命中，能正常完成地址转换了。

2）影响 Cache 性能的因素有哪些？

Cache 系统的访存效率主要由命中率决定，而命中率受多种因素影响：

① 映射方式：全相联映射命中率最高，直接映射最低，组相联介于两者之间。

② Cache 容量：容量越大，可缓存的数据越多，命中率通常越高。

③ 块大小（Cache 行大小）：块过小难以利用空间局部性，过大则可能降低有效容量并增加缺失损失，因此需取适中值。

此外，Cache级数（单级或多级）、指令/数据 Cache 是否分离、以及主存-总线-Cache-CPU 的架构等，也会显著影响 Cache 的总体性能。

3）虚拟存储系统的页面是设置得大一些好还是设置得小一些好？

页面大小应适中，过大或过小均会带来问题。页面过小：页表项数量剧增，导致页表庞大；同时难以有效利用空间局部性，降低命中率。页面过大：虽可减小页表规模，但会增加页内碎片，浪费内存空间，且页面调入/调出时传输开销更大，延长缺页处理时间。因此，实际系统通常选择4KB～几MB的页面大小，在页表开销、局部性利用与I/O效率之间取得平衡。

## 3.8 常见问题和易混淆知识点

1. Cache 行的大小和命中率之间有什么关系？

当 Cache 行较大时，能更好利用空间局部性，将更多的相邻数据一次性调入 Cache，从而提高命中率。但行长不宜过大，主要原因有两个：

① 行长过大会增加缺失损失，即未命中时需从主存读取更多数据，传输时间更长。

② 在 Cache 总容量固定的情况下，行长增大会导致行数减少，降低地址映射的灵活性，反而可能降低命中率。

反之，行长过小虽使缺失代价较小，但难以有效利用空间局部性，命中率通常偏低。

2. 发生取指令 Cache 缺失的处理过程是什么？

当发生取指令 Cache 缺失时，系统按以下步骤处理：

1）保持程序计数器不变，确保缺失处理完成后能重新获取同一条指令。

2）根据 PC 指向的地址，从主存读取该指令。

3）将该指令所在主存块调入 Cache，并更新对应 Cache 行的有效位和标记位。

4）重新从 Cache 中取指并继续执行。

## 二、B为什么对？

B 说:

采用直接存储器存取DMA方式进行输入/输出。

这个也是对的。

磁盘属于外部设备，数据量通常比较大。如果每个字节都让CPU搬运，效率很低。

所以磁盘 I/O 常用 DMA。

过程大概是：

1. CPU 向磁盘控制器发出读/写命令;

2. CPU 设置 DMA 控制器，比如主存地址、传送长度、传送方向；

3. DMA 控制器控制磁盘和主存之间的数据传送；

4. 传送完成后，用中断通知 CPU。

关键点是：

DMA 让数据在磁盘和主存之间直接传送，减少 CPU 干预。

## 四、D 为什么错？

D 说:

磁盘存储器可与CPU交换盘面上的存储信息。

这句话错误的关键在于：对象写错了。

磁盘上的数据通常不是直接和 CPU 交换，而是：

磁盘 $\leftrightarrow$ 主存

CPU 主要负责:

\- 发出 I/O 命令;

\- 设置 DMA;

\- 检查状态;

\- 传送结束后处理中断。

真正大量数据传输过程一般是：

磁盘 $\rightarrow$ 磁盘控制器 $\rightarrow$ DMA $\rightarrow$ 主存

或者：

主存 $\rightarrow$ DMA $\rightarrow$ 磁盘控制器 $\rightarrow$ 磁盘

不是:

磁盘 $\leftrightarrow$ CPU

所以D错在把主存写成了CPU。

20. 【2024统考真题】下列事件中，不是在MMU地址转换过程中检测的是（）。A. 访问越权 B. Cache缺失 C. 页面缺失 D. TLB缺失

20. B

在地址转换的过程中，MMU 会检查页表项的访问权限，以确保进程有权访问某个页面，否则就会访问越权。为了获得对应的页表项，先查找 TLB，若找不到，则 TLB 缺失，然后查找页表，若找不到，则页面缺失。访问 Cache 是在获得物理地址后使用物理地址存取数据的过程中才执行的操作，而 MMU 地址转换过程是在获得物理地址之前进行的，选项 B 错误。
